## §0 四条硬规则

1. **四段生命周期**（`stages`）：`discovered` → `fixed` → `testVerified` → `postReleaseReviewed`。
2. **四个独立状态**（`flags`）：`designed`（设计已定义）· `coded`（代码已修改）· `unitTested`（单元/集成通过）· `e2eVerified`（端到端/故障注入通过）—— **四者不可混同**，尤其：
   - **"只改代码无测试"不得标"已完成验收"**（门禁：`unitTested ⇒ tests 非空`）；
   - **不得跳过单元直称端到端**（门禁：`e2eVerified ⇒ unitTested`）；
   - `fixed ⇒ code 非空`；`postReleaseReviewed ⇒ changelog 非空 且 testVerified`。
3. **自动重开**：后续版本若**撤销修复 / 改默认值 / 移除组件**，对应条目须**重新打开**（`reopenWhen` 列即判据）。
4. **不留悬空状态**：条目的 `stages/flags` 必须与证据一致（由 `lint:fix-evidence` 双向校验）。

## §3 自动重开判据（何时必须重开条目）

- **撤销修复**（revert）或**移除相关组件** ⇒ 对应 ID 立即重开（`code` 路径消失即门禁变红）；
- **改默认值**（安全开关 / 灰度）⇒ 重开对应条目并复核 `stages`；
- **CHANGELOG 声明修复但无测试** ⇒ 不得置 `unitTested=true`（门禁阻断）。
