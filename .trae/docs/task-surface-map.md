# 「任务家族」术语 / 存储 / 入口 对照表（#26）

> 目的：把「任务 / 计划 / PDCA / 工作项 / 后台任务 / 定时任务」这几个**同名不同义**的词，
> 收敛成一张可查的表 —— 每个词只有一处语义、一处存储、一处入口。
> 本文只记录**现状事实**与**已定裁定**；未定项标注为「待裁定」，不在代码里替用户拍板。

## 一、对照表

| 术语 | 唯一语义 | 存储（权威表） | 页面入口 | 状态 |
|---|---|---|---|---|
| **定时任务**（cron） | 按 cron 表达式周期触发的调度作业 | `cron_*`（CronPage 数据源） | `/cron`；左侧导航「定时任务」；工作台「Agent 与自动化 → 定时任务」 | ✅ 唯一入口；`/tasks` 亦指向它（历史兼容，见下） |
| **运行状况**（原「后台任务」） | Dream 记忆整理 / Buddy 成长等**后台运行**的执行观测 | `backgroundTaskService` 读取的运行记录 | `/background-status`（页面 h2 =「运行状况」） | ✅ 导航名已对齐页面（#26）；与待办无关 |
| **PDCA** | 项目内的「执行计划 / 执行流程 / PDCA 检查点」编排 | `pdca_checkpoints`(184) + 项目 items | 项目详情 →「编排」 | ✅ 入口唯一；与 `/tasks` **不同源** |
| **工作项**（work item） | 项目看板上的工作条目 | `workitems`(16) 在用 | 项目详情 → 看板 | ✅ 单表（`work_items` 空表已于 2026-10-30 下线，见 §二） |
| **长期目标**（goal） | 长程任务的目标与执行审计痕迹 | `task_goals`(879) / `task_audit_log`(31379) | **无独立页面**（作为执行痕迹被引用） | ⚠️ 概念与「工作项/任务」重叠 |
| **任务节点**（task node） | 项目内的人工任务条目（P0–P3 / 状态筛选） | `tasks`（0 行；唯一写入方 `workspace/TaskStore`） | 仅 API `GET /v1/tasks`（`TasksPage` 已于 2026-10-31 下线删除） | ✅ 语义已定（M10-C）；页面入口不恢复 |
| **计划**（plan） | 全局「计划」= 定时任务（cron）；项目内「编排」= pdca | `cron_*` / `pdca_checkpoints` | `/plans` → `/cron`；项目详情「编排」 | ✅ 语义已定（M12-B） |

## 二、已定裁定 / 变更记录

- **2026-10-30（用户裁定，见 #25 注释）**：`/tasks` 改挂「定时任务」（`CronPage`），导航名改为
  「定时任务」。
- **2026-10-31（用户裁定）**：原 `TasksPage`（任务聚合收件箱）**正式下线并删除**
  （数据源 `tasks` 表 0 行、M10-C 已定"仅保留 API"）；`GET /v1/tasks` 与服务层保留不动。
- **#26（本单）**：
  1. 导航 `nav.backgroundStatus` 由「后台任务」改为「运行状况」，与页面标题一致；
  2. `/plans` 重定向改为 `/cron`（此前跳 `/tasks`，而 `/tasks` 已是定时任务页 ⇒ URL 名与页面错位）；
  3. 项目详情「成果」页签加口径说明：列的是**文件**，不是任务/工单数据。

## 三、已裁定（2026-10-30，用户决策）

1. **任务域双表边界（M10-C）**：保留双表、**只明确边界** ——
   `tasks` = 项目**人工任务节点**（唯一写入方 `workspace/TaskStore`，API `/v1/tasks`）；
   `workitems` = **PDCA 执行项**（唯一写入方 `tasks/PdcaWorkItemBridge`）；
   `task_goals` = **长程目标**（聊天区目标条）；`cron_*` = **定时任务**。不迁移数据、不合并表。
   守卫：`app/tests/tasks/taskSurfaceBoundaries.test.ts`（表名常量全仓唯一 + 互不写对方表）。
2. **「计划」入口（M12-B）**：保留两套 —— 全局「计划」= cron（`/plans` 仍重定向 `/cron`，
   全局导航**不**出现指向 pdca 的「计划」入口）；项目内「编排」= pdca（项目详情内可见）。
   守卫同上测试文件的 M12-B 两条断言。

## 五、维护约定

- 新增任何「任务/计划/待办」相关入口，**必须**先在本表登记「词 → 表 → 页面」三列；
- 同一词不得出现第二处入口（`navRegistry` 是导航入口唯一事实来源）；
- 表名以 DB 实际表为准，禁止在 UI 文案里用未登记的近义词（如同义混用「待办 / TODO / 工单」）。
