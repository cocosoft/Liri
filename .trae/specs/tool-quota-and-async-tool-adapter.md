## 1. 背景与裁定

- **D8 裁定（2026-10-11）**：方向**采纳**「虚拟工具代理契约（N3）」——内核**不区分**同步/异步；
  长耗时重型工具定义为 **MCP 侧车**，由网关返回结构化占位符 + 抛 `AgentSuspensionEvent`，
  由 `ExecutionManager` 捕获触发持久化冻结；**不在工具治理主方案实施**，**立独立 spec**（本文）。
- **与既有实现的关系（CS01）**：本仓**已有**三处可复用基座，**不新建子系统**：
  | 基座 | 位置 | 现状 |
  |---|---|---|
  | 会话级工具调用总配额 | `app/src/tools/sessionToolQuota.ts` | 单会话总上限（默认 150，超限**降级提示**） |
  | 断路器（三态） | `app/src/query/CircuitBreaker.ts` | **Agent 循环**连续失败 → OPEN/HALF_OPEN/CLOSED |
  | 策略限额 | `app/src/services/policyLimits/**` | user/org/session 日限额（远端 API，`enabled` 默认关） |
- **缺口**：**无按工具（per-tool）的滑动窗口配额**；**无**"内核不区分同步/异步"的代理形态。

---

## 2. 范围

- **做（本 spec 立项后）**：
  1. **per-tool 滑动窗口配额/熔断** —— 复用 `sessionToolQuota` 的"双约束（hard/soft）"形态与
     `CircuitBreaker` 的三态机，扩为**按工具**维度（示例：`bash` 5min/20 次、生图 50/天）；
     超限**降级为可读提示**（非静默失败，对齐既有 sessionQuota 口径）。
  2. **两阶段异步工具（虚拟工具代理契约）** —— 内核不区分同步/异步；重型工具作 MCP 侧车，
     网关返回结构化占位符（如 `{status:'processing', est_duration:300}`）+ 抛 `AgentSuspensionEvent`；
     `ExecutionManager` 捕获后触发**持久化冻结**。
- **不做**：
  - **不**在工具治理主方案内实施（本 spec 独立立项、独立提交）。
  - **不**引入与 `events.jsonl → SQLite WAL` 迁移的耦合（后者属附录 D 另案）。
  - **不**硬编码工具名/阈值（阈值经配置/DB，遵循"模型与策略数据化"惯例）。

## 3. 触发条件（立项前置，满足后开工）

- **T1**：per-tool 配额 —— 出现**实测**证据表明某工具被（模型或代码）高频重复调用并造成
  可观测损害（成本/限流/副作用）。**当前观测入口**：`tools/monitoring/ToolMetrics.ts`
  （`tools.invocation.*`，含 `result`、耗时、入参字节、估算 tokens）—— **先观测，再立项**。
- **T2**：两阶段异步 —— **D10 侧车成形**（至少一个重型工具以侧车形式接入）后，才有"结构化占位符 +
  `AgentSuspensionEvent`"的真实生产者；否则实现即**投机扩展**（CS03）。
