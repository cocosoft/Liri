## 1. 结论先行：已定位"提前终止"的**根因**（P0）

### 1.1 现象

用户在 11 轮里被同一句话打断 **4 次**（21:57、22:03、00:07、00:08），文案固定：

```
⚠️ 已达到本轮 token 预算上限，工具链提前终止。
```

### 1.2 运行时铁证（这是全链条最硬的一环）

`app.log` 中对 `reActLoop:budget_exhausted` **全文仅 1 条有效命中**：

```
2026-09-25T16:07:02.581Z  query:reactLoop  reActLoop:budget_exhausted
meta: {"maxIterations":200,"iteration":72}
```

- 该时刻 = 本地 **00:07:02**，与导出中被终止的那条助手消息（`### 🤖 助手 (2026/9/26 00:07:02)`）**精确对应**。
- **关键异常**：`iteration = 72` 而 `maxIterations = 200` ⇒ **不是在轮次上限触顶**，而是被**另一条预算**在 72/200 处掐断。
- 早先那两次终止（21:57 / 22:03 本地）不在本日志中，原因是**日志在 23:42:48 本地轮转过**（§0②）——不是矛盾。

### 1.3 机制链（逐段均已读码）

```

              （被 ReActToolLoop._chargeStreamBudget() 每轮调用，L3266 / 调用点 L2896、L3191）
```

### 1.4 根因判定（**量纲错配**）

| 概念 | 语义 | 本实现的用法 |
|---|---|---|
| `context_window`（DB `model_registry.context_window`） | **瞬时容量**："一次请求最多能装多少" | 被当作 **`total`** 预算 |
| 每轮 `chargeContextEstimate(估算上下文)` 的增量 | **流量**："累计消耗了多少" | 单调累加，且**只增不减** |

⇒ **把"窗口"当"预算"扣、且不退款** ⇒ 累计增长一旦触及窗口即 `EXCEEDED`，此后**永久 EXCEEDED**（只能靠"每 run 一次"的 `needsGraceCall` 收尾）。
⇒ 于是"轮次预算 200"与"实际终止于 72"并不矛盾：**先撞的是 token 预算，不是轮次**。

### 1.5 与"已修的两个根因"的区别（避免误判为同一问题）

| 根因 | 状态 | 关系 |
|---|---|---|
| 工具轮次扩容公式（0.5 轮/轮衰减，约 59 轮撞线） | ✅ 已修（`ReActToolLoop.ts` 新续期公式） | **不同**：那是 `maxIterations` 侧 |
| 轮次预算不跨 run 持久化 | ✅ 已修（`budgetBaseline` / `taskKey` / `isSystemResume`） | **不同**：那是**轮次**的跨段继承 |
| **上下文窗口被当累计预算扣（本项）** | ⚠️ **未修 / 未裁定** | **本次新定位**，是 token 侧 |

### 1.6 顺带发现：注释与实现不一致（同一根路径上）

`ReActLoopConfig.budget` 的注释写"**ReActToolLoop 默认不启用，能力预留**"，但 `createAgentLoop.ts:117-123` 对流式路径**默认注入** `createStreamBudget(model)` ⇒ 注释已过时，且过时点恰在**核心终止路径**上（会误导排查者以为"这条分支不会走"）。

### 1.7 P0 待裁定问题（**需人决策，非纯技术**）

1. **量纲是否正确？** 若"窗口 = 预算"是有意设计，则应在文案/文档中说明"上限=窗口"；若否，应改为按**当前上下文占用**判定（而非累计）。
2. **compact 回落后是否应退款？** 现语义"只降基线不退款"使预算**不可逆**。
3. **grace call 每 run 仅一次**是否足够（长任务里一次收尾通常不足）。
4. 与另外两套 token 口径的关系：`ToolResultBudget`（工具结果预算）、`MoaCostController`（总 Token 预算）、`types.ts:44`（**每日** Token 预算）——**是否叠加**、优先级如何。
5. `checkBudget()` 的 WARNING/CRITICAL/EXCEEDED 阈值在长会话中是否会"长期贴着 CRITICAL"。
