# 会话消息割裂问题根治方案

> 编写日期：2026-06-01
> 对标参考：CJL_REF/cline-main
> 核心方法：流式输出内容的顺序化与结构化管理

---

## 一、问题本质分析

### 1.1 当前数据流的断裂

```
后端 LLM 流式输出（纯文本，含工具调用标记）
  ↓
CoreAPIImpl.chatStream() 拆解为三类独立事件：
  ├─ "text" chunks     → SSE 流（连续）
  ├─ "tool_call" chunks → SSE 流（通过 onToolCall 回调触发）
  └─ "status" chunks   → SSE 流（通过 onToolCall 回调触发）
  ↓
chatStore.ts 接收这三类事件并构建 blocks[]：
  ├─ text      → findOrCreateBlock('text') → 合并到同一个 text block
  ├─ tool_call → blocks.push(toolCallBlock)
  └─ status   → blocks.push(statusBlock)
  ↓
blocks[] 顺序错误：
  [text(全部内容), status, tool_call, status]     ← ❌ 当前
  期望顺序：
  [text(前半), status, tool_call, status, text(后半)]  ← ✅ 正确
```

### 1.2 根因

| 根因 | 说明 |
|------|------|
| **R1：text block 被单块复用** | `findOrCreateBlock('text')` 始终找到同一个 text block，工具调用前后的文本被合并到一块 |
| **R2：三类事件不同源** | text 来自 LLM 流，tool_call/status 来自 `onToolCall` 回调，**不同源导致时序乱序** |
| **R3：缺少 partial 标记** | 没有区分"正在流式中的块"和"已完成块"，导致重建 blocks 时无法正确截断 |
| **R4：历史恢复时 blocks 不完整** | `persistMessage`/`updateMessageBlocks` 写入的 blocks 结构与流式时的 blocks 结构不一致 |

### 1.3 Cline 参考方案的关键设计

| Cline 设计 | 对应 py-app 缺陷 |
|-----------|----------------|
| **单一文本流解析**：LLM 输出纯文本 → `parseAssistantMessageV2` 实时解析为 content blocks（text / tool_use / reasoning），**所有 block 来自同一个流** | 三类事件不同源 |
| **partial 标记**：每个 block 有 `partial: boolean`，流式未完成时标记为 partial | 无 partial 标记 |
| **顺序索引**：`currentStreamingContentIndex` 按序消费 blocks | 无顺序控制 |
| **展示锁**：`presentAssistantMessageLocked` 防止并发显示 | 无并发控制 |

---

## 二、根治方案

### 总策略

**前端改造**（方案 A，无需修改后端流式架构）：

放弃 `findOrCreateBlock` 按 type 找块的逻辑，改为 **按流顺序创建块**。每次 tool_call/status 到来时，**截断当前 text block**，工具调用结束后，**新建 text block** 继续。

---

## 三、具体修改

### 修改 1：引入 `ChronologicalBlockBuilder`

**文件**：`client/src/stores/chatStore.ts`

新增 `ChronologicalBlockBuilder` 类，替代 `findOrCreateBlock`：

```typescript
/**
 * 时序块构建器
 * 
 * 核心职责：按流顺序构建 MessageBlock[]，确保工具调用前后的文本正确分段。
 * 对标 Cline 的 assistantMessageContent[] 顺序管理。
 * 
 * 设计原理：
 * 1. text/thinking chunk → 写入当前"活跃文本块"
 * 2. tool_call chunk →  冻结当前活跃文本块（isStreaming=false），新建 tool_call 块
 * 3. status chunk   →  追加到末尾（标记当前工具调用的开始/结束）
 * 4. tool_call 执行完成 → 解冻，新建 text 块继续接收
 * 5. 流结束 → 冻结所有块
 */
class ChronologicalBlockBuilder {
  private blocks: MessageBlock[] = [];
  private activeTextBlock: MessageBlock | null = null;
  private activeThinkingBlock: MessageBlock | null = null;
  private hasToolCallSinceLastText = false;

  /**
   * 添加或追加文本块
   * 如果 hasToolCallSinceLastText 为 true，则新建文本块而非追加
   */
  addText(content: string, isStreaming: boolean): void {
    if (this.hasToolCallSinceLastText || !this.activeTextBlock) {
      // 工具调用结束后或首次，新建 text 块
      const newBlock: MessageBlock = {
        id: generateBlockId(),
        type: 'text',
        content,
        isStreaming,
      };
      this.blocks.push(newBlock);
      this.activeTextBlock = newBlock;
      this.hasToolCallSinceLastText = false;
    } else {
      // 追加到当前 text 块
      this.activeTextBlock.content += content;
      this.activeTextBlock.isStreaming = isStreaming;
    }
  }

  /**
   * 添加 thinking 块
   */
  addThinking(content: string, isStreaming: boolean): void {
    if (!this.activeThinkingBlock) {
      const newBlock: MessageBlock = {
        id: generateBlockId(),
        type: 'thinking',
        content,
        isStreaming,
      };
      this.blocks.push(newBlock);
      this.activeThinkingBlock = newBlock;
    } else {
      this.activeThinkingBlock.content += content;
      this.activeThinkingBlock.isStreaming = isStreaming;
    }
  }

  /**
   * 冻结 thinking 块（text 到来时调用）
   */
  freezeThinking(): void {
    if (this.activeThinkingBlock) {
      this.activeThinkingBlock.isStreaming = false;
      this.activeThinkingBlock = null;
    }
  }

  /**
   * 添加状态块（直接追加到数组末尾）
   */
  addStatus(status: string): void {
    // 去重：如果最后一个 status 内容相同则跳过
    const lastBlock = this.blocks[this.blocks.length - 1];
    if (lastBlock?.type === 'status' && lastBlock.content === status) {
      return;
    }
    this.blocks.push({
      id: generateBlockId(),
      type: 'status',
      content: status,
      isStreaming: true,
    });
  }

  /**
   * 添加工具调用块
   * 冻结当前 text 块，插入 tool_call 块，标记 hasToolCallSinceLastText
   */
  addToolCall(toolCall: ToolCall): void {
    // 冻结当前 text 块
    if (this.activeTextBlock) {
      this.activeTextBlock.isStreaming = false;
    }
    if (this.activeThinkingBlock) {
      this.activeThinkingBlock.isStreaming = false;
      this.activeThinkingBlock = null;
    }

    // 查找是否已有相同 toolCall.id 的块
    const existingIdx = this.blocks.findIndex(
      (b) => b.type === 'tool_call' && b.toolCall?.id === toolCall.id
    );

    if (existingIdx !== -1) {
      // 更新已有块
      const existing = this.blocks[existingIdx];
      existing.toolCall = { ...toolCall, status: toolCall.status || 'completed' };
      existing.isStreaming = toolCall.status === 'running';
    } else {
      // 新建 tool_call 块
      this.blocks.push({
        id: generateBlockId(),
        type: 'tool_call',
        content: '',
        toolCall,
        isStreaming: true,
      });
    }

    this.hasToolCallSinceLastText = true;
  }

  /**
   * 更新已有工具调用的状态（running→completed/failed）
   */
  updateToolCallStatus(toolCallId: string, status: 'running' | 'completed' | 'failed'): void {
    const block = this.blocks.find(
      (b) => b.type === 'tool_call' && b.toolCall?.id === toolCallId
    );
    if (block && block.toolCall) {
      block.toolCall.status = status;
      block.isStreaming = status === 'running';
    }
  }

  /**
   * 冻结所有块（流结束时调用）
   */
  freezeAll(): void {
    for (const block of this.blocks) {
      block.isStreaming = false;
    }
    this.activeTextBlock = null;
    this.activeThinkingBlock = null;
  }

  /**
   * 获取构建好的 blocks
   */
  getBlocks(): MessageBlock[] {
    return [...this.blocks];
  }

  /**
   * 重置构建器状态
   */
  reset(): void {
    this.blocks = [];
    this.activeTextBlock = null;
    this.activeThinkingBlock = null;
    this.hasToolCallSinceLastText = false;
  }
}
```

### 修改 2：简化 streamMessage 使用 ChronologicalBlockBuilder

**文件**：`client/src/stores/chatStore.ts`

```typescript
streamMessage: async (content: string, sessionId?: string) => {
  // ... 初始化 userMessage 和 assistantMessage ...

  const blockBuilder = new ChronologicalBlockBuilder();

  try {
    const generator = chatService.streamMessage(content, sessionId);

    for await (const chunk of generator) {
      const current = get().messages;
      const msgIdx = current.findIndex((m) => m.id === assistantId);
      if (msgIdx === -1) continue;

      if (chunk.type === 'thinking') {
        blockBuilder.addThinking(chunk.content, true);
      } else if (chunk.type === 'text') {
        blockBuilder.freezeThinking();
        blockBuilder.addText(chunk.content, true);
      } else if (chunk.type === 'status') {
        blockBuilder.addStatus(chunk.content);
      } else if (chunk.type === 'tool_call' && chunk.toolCall) {
        blockBuilder.addToolCall(chunk.toolCall);
      } else if (chunk.type === 'usage' && chunk.usage) {
        // 不处理 usage
      }

      const newMessages = [...current];
      newMessages[msgIdx] = {
        ...current[msgIdx],
        content: current[msgIdx].content, // 保持 content 同步
        blocks: blockBuilder.getBlocks(),
      };
      set({ messages: newMessages });
    }

    // 流结束，冻结所有块
    blockBuilder.freezeAll();
    // ... 保存 blocks 到后端 ...
  }
}
```

### 修改 3：AssistantMessage 渲染统一

**文件**：`client/src/components/ChatArea/ChatMessage.tsx`

```typescript
function AssistantMessage({ message, isStreaming }: { message: Message; isStreaming?: boolean }) {
  let blocks = message.blocks;

  // 无 blocks 时从 content + tool_calls 重建
  if (!blocks || blocks.length === 0) {
    blocks = buildFallbackBlocks(message);
  }

  const renderedContent = renderBlocksWithGroups(blocks, isStreaming);
  return (
    <div className="text-sm break-words max-w-none space-y-3">
      {renderedContent}
    </div>
  );
}
```

**说明**：无需修改 `renderBlocksWithGroups`，它已经正确处理了**连续 tool-related blocks 的分组**。`ChronologicalBlockBuilder` 保证了 blocks 的自然顺序就是正确的分组顺序。

## 五、预期效果

### 5.1 流式传输中

```
输入 blocks 构建过程（按流顺序）：
1. text("你好")                 → blocks: [text("你好")]
2. thinking("让我想想...")       → blocks: [text("你好"), thinking("让我想想...")]
3. text("我来帮你")             → blocks: [text("你好"), text("我来帮你")]  // thinking 被冻结
4. status("Running read_file") → blocks: [text("你好"), text("我来帮你"), status("Running read_file")]
5. tool_call(read_file)        → blocks: [text("你好"), text("我来帮你"), status("Running read_file"), tool_call(read_file)]
6. status("Completed")         → blocks: [... , status("Completed")]
7. text("查到了，内容如下：")   → blocks: [text("你好"), text("我来帮你"), ..., text("查到了，内容如下：")]  // 新建 text 块
```

### 5.2 历史记录加载

后端持久化的 blocks 已经是正确顺序，切换回会话时：
```
blocks 直接使用 → AssistantMessage 渲染 → 按顺序显示 ✅
```

### 5.3 与 Cline 的对标

| 维度 | Cline | py-app（修复后） |
|------|-------|----------------|
| 块解析方式 | 实时解析原始文本流 | `ChronologicalBlockBuilder` 按事件顺序构建 |
| 块顺序控制 | `currentStreamingContentIndex` | 按 blocks 数组自然顺序 |
| text 分段 | 每段文本对应一个 `TextStreamContent` | 每次 tool_call 后新建 text 块 |
| partial 标记 | 每个 block 有 `partial: boolean` | 每个 block 有 `isStreaming: boolean` |
| 工具调用标识 | `tool_use` 内嵌在文本流中 | `tool_call` + `status` 事件 |
