# 模型数据完全剥离方案

## 问题现状

`app/src/ai/models/ModelConfigs.ts` 中仍有 **40 个模型**的完整配置硬编码在 `ALL_MODEL_CONFIGS` 中。每个模型包含：

| 字段 | 数量 | 示例 |
|------|------|------|
| 提供商映射名 | ~10 个 | firstParty, bedrock, vertex, azure, openai, deepseek, google, grok, moonshot, ollama |
| 元数据 | 3 个 | displayName, contextWindow, maxOutputTokens |
| 能力列表 | 1 个 | 10-15 项能力枚举 |
| 定价 | 2-4 个 | inputPer1M, outputPer1M, cacheReadPer1M?, cacheWritePer1M? |
| 扩展上下文 | 1 个 | extendedContextWindows |

合计约 **40 × 20 = 800 行**硬编码数据。虽然 `ModelRegistry`、`ConfigLoader`、前端管理页面已就绪，但**数据源本身**仍来自 TS 常量，没有真正剥离。

---

## 目标

把所有模型数据从 TypeScript 中**完全移入 YAML 配置文件**，TS 只保留类型定义和加载逻辑。

---

#### 3.2 ModelRegistry 重构

```typescript
class ModelRegistry {
  private models: Map<string, ModelConfig>;

  constructor() {
    this.models = new Map();
  }

  loadDefaultModels(): void {
    // 从嵌入的 YAML 字符串加载内置默认模型
    const data = load(DEFAULT_MODELS_YAML) as ModelsConfigFile;
    for (const [id, cfg] of Object.entries(data.models)) {
      this.models.set(id, cfg);
    }
  }

  loadUserModels(): void {
    // 从 ~/.pyapp/models.yaml 加载用户覆盖
    const userPath = join(resolvePyappHome(), 'models.yaml');
    if (existsSync(userPath)) {
      const data = load(readFileSync(userPath, 'utf-8')) as ModelsConfigFile;
      for (const [id, cfg] of Object.entries(data.models)) {
        this.models.set(id, cfg);
      }
    }
  }

  getAllModels(): ModelConfig[] {
    return Array.from(this.models.values());
  }

  getModel(modelId: string): ModelConfig | undefined {
    return this.models.get(modelId);
  }
}
```

#### 3.3 启动流程调整


#### 4.3 `getModelKeyByName` 迁移

```typescript
// 在 ModelRegistry 中新增
class ModelRegistry {
  getModelKeyByName(modelName: string): string | null {
    for (const [key, config] of this.models) {
      for (const providerName of Object.values(config.providers)) {
        if (providerName === modelName) return key;
      }
    }
    return null;
  }
}
```

### Phase 5: 迁移工具 + 验证（1 天）

#### 5.1 数据迁移脚本

```typescript
// scripts/export-models-to-yaml.ts
// 从 ALL_MODEL_CONFIGS 导出 YAML

import { writeFileSync } from 'fs';
import { dump } from 'js-yaml';
import { ALL_MODEL_CONFIGS } from '../src/ai/models/ModelConfigs';

const output: Record<string, unknown> = { models: {} };

for (const [key, config] of Object.entries(ALL_MODEL_CONFIGS)) {
  const model = config as any;
  output.models[key] = {
    displayName: model.displayName,
    contextWindow: model.contextWindow,
    maxOutputTokens: model.maxOutputTokens,
    capabilities: model.capabilities?.map((c: string) => c.toLowerCase()),
    providers: {
      firstParty: model.firstParty || undefined,
      bedrock: model.bedrock || undefined,
      vertex: model.vertex || undefined,
      azure: model.azure || undefined,
      openai: model.openai || undefined,
      deepseek: model.deepseek || undefined,
      google: model.google || undefined,
      grok: model.grok || undefined,
      moonshot: model.moonshot || undefined,
      ollama: model.ollama || undefined,
    },
    pricing: model.pricing || undefined,
    extendedContextWindows: model.extendedContextWindows || undefined,
  };

  // 清理空字符串
  for (const [k, v] of Object.entries(output.models[key].providers)) {
    if (!v) delete output.models[key].providers[k];
  }
  if (Object.keys(output.models[key].providers).length === 0) {
    delete output.models[key].providers;
  }
}

writeFileSync('models.default.yaml', dump(output), 'utf-8');
console.log('已导出 models.default.yaml');
```

## 风险与缓解

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 引用替换遗漏导致编译错误 | 高 | `tsc --noEmit` 全覆盖，逐个修复 |
| YAML 数据类型与 TS 不匹配（如字符串 vs 数字） | 中 | 使用 `zod` 或手动校验 Schema |
| 空字符串 provider 字段（如 `openai: ''`）污染 YAML | 低 | 迁移脚本中排除空字符串 |
| 用户已有 providers.yaml 但无 models.yaml | 中 | `loadDefaultModels()` 确保总有内置回退 |
| ModelAliases.ts 与 ModelConfigs 循环依赖 | 中 | ModelAliases 改为纯函数 + ModelRegistry 查询 |
