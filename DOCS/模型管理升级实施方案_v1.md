# 模型管理系统升级 — 可执行实施方案

## 评估结论：方案不能直接执行

经逐项比对 v3 方案与当前代码库，结论如下：

| 维度 | 评估 |
|------|------|
| **已实现** | Provider CRUD、预设 8 厂商、定价编辑、连接测试、定价同步、配置热重载（约 30% 工作量已就绪） |
| **需新建** | 状态栏模型指示器、快速切换面板、按任务分工策略、模型元数据编辑器（约 60% 需新建） |
| **方案欠缺** | v3 未指定：API 类型定义、数据流设计、依赖顺序、测试策略、已实现部分的对齐 |
| **总评** | ❌ **不能直接执行**。需先写分阶段实施方案，明确每一大步的文件/API/Schema 变更 |

**新增文件**: `client/src/services/modelDiscoveryService.ts`

```typescript
export const modelDiscoveryService = {
  async discoverFromEndpoint(baseUrl: string): Promise<string[]> {
    // 调用 {baseUrl}/v1/models 获取模型列表
    const response = await fetch(`${baseUrl.replace(/\/$/, '')}/v1/models`);
    const data = await response.json();
    return data.data?.map((m: any) => m.id) ?? [];
  },
};
```

集成到 Provider 编辑弹窗：

```
Base URL: [http://localhost:11434/v1    ]  [自动发现▼]
                                         └─ 点击 → 调用 discoverFromEndpoint
                                         └─ 自动填充模型列表
```

```typescript
class ModelManager {
  async getModelWithFallback(taskType: string): Promise<{ model: string; isFallback: boolean }> {
    const primary = this.getModelForTask(taskType);
    try {
      // 快速健康检查
      const provider = this.getProviderForModel(primary);
      await provider.ping();
      return { model: primary, isFallback: false };
    } catch {
      const fallback = this.getConfig().fallback || this.getSmallFastModel();
      return { model: fallback, isFallback: true };
    }
  }
}
```

## 执行建议

1. **P1 优先**：状态栏指示器 + 切换面板是用户感知最强、性价比最高的功能
2. **P3 与 P4 可并行**：元数据编辑器和列表增强互不依赖
3. **P5 可拆分**：自动降级为后端特性，与前端对比/导入导出无关
4. **每个 Phase 结束都跑 `typecheck`**：确保 TS 类型正确
