# 模型管理系统优化建议方案

## 一、现状概述

当前模型管理系统由 `app/src/ai/models/` 核心模块承载，配合命令层、客户端层和多个辅助模块，构成以下体系结构：

```
┌─────────────────────────────────────────────────────────────────────┐
│                       模型管理系统架构总览                           │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  【数据层】                                                         │
│  ModelConfigs.ts ─── ALL_MODEL_CONFIGS（38+ 模型，全部硬编码）      │
│                                                                     │
│  【核心服务层】                                                     │
│  ModelManager.ts ─── 配置管理、别名解析、模型选择、定价查询         │
│  AIModelManager.ts ── 别名解析、Thinking 配置、Provider 自动匹配    │
│  ModelStringService.ts ── 模型字符串解析/渲染的委托层               │
│                                                                     │
│  【展示层】                                                         │
│  ModelDisplay.ts ─── 格式化展示、成本计算、模型比较                 │
│  ModelAliases.ts ─── 别名定义（sonnet/opus/haiku/best）             │

│  core/tokenBudget/PriceManager.ts ─── 内置价格 + 提供商模式         │
│                                                                     │
│  【命令层】                                                         │
```

## 二、核心优势（需保留的设计亮点）

| 特性 | 说明 |
|------|------|
| **单一事实源** | `ALL_MODEL_CONFIGS` 集中管理 38+ 模型的全部配置 |
| **多提供商支持** | 每个模型支持 firstParty/bedrock/vertex/azure/openai 等 10 种提供商 ID |
| **分层委托架构** | ModelManager → AIModelManager → ModelStringService，职责分明 |
| **模型能力枚举** | `ModelCapability` 枚举 + `capabilities` 字段，支持精细能力声明 |
| **环境变量覆盖** | `ANTHROPIC_DEFAULT_OPUS_MODEL` 等支持运行时覆盖默认模型 |
| **别名系统** | 支持 sonnet/opus/haiku/best 别名及 `[1m]` 上下文扩展后缀 |

## 三、UI_REF 对标分析

对 `UI_REF/` 下 4 个前端项目的模型管理模块进行了深度分析，总结如下：

### 3.1 OpenClaw-Admin（Vue.js + Pinia）

**设计哲学**: 配置驱动（Configuration-driven），模型数据全部通过配置文件管理

| 特性 | 实现方式 |
|------|---------|
| Provider CRUD | 完整的创建/编辑/删除 Provider 操作，支持 `openai-completions`/`anthropic-messages`/`google-generative-ai` 等协议 |
| 配置持久化 | 以 `ConfigPatch{path, value}` 方式写入配置文件（`models.providers.<id>.*`），非数据库 |
| 快速预设 | 内置智谱 GLM、Kimi、MiniMax、百炼等国内厂商一键配置 |
| Provider 表格 | 显示 Provider ID、协议、Base URL、模型列表、操作按钮（编辑/设为主力/删除） |
| 变更预览 | 保存前展示完整 diff（api/baseUrl/modelIds 的 before/after），含警告和自动修复建议 |
| 模型输入类型 | 支持 `text`/`image` 输入类型声明，标注在多模态模型上 |
| 别名系统 | 模型通过 `providerId/modelId` 格式引用，支持配置级别名映射（`agents.defaults.models`） |
| 引用自动同步 | 修改 Provider 的模型列表时，自动同步所有引用配置（agents.defaults.models、agent list 等） |

**前端 UI 截图参考**: [UI_REF/OpenClaw-Admin-main/docs/images/模型管理.png]

### 3.2 Hermes Web UI（Python + Vanilla JS）

**设计哲学**: 动态端点发现（Dynamic Endpoint Discovery）

| 特性 | 实现方式 |
|------|---------|
| 内置 Provider 定义 | 通过 `HERMES_PROVIDERS` 常量声明已知提供商（Anthropic、OpenAI、Google 等） |
| 自定义端点 | 用户可添加任意 `custom_providers`，指定 `name` + `base_url` + `models` |
| 凭据管理 | API Key 通过环境变量管理，界面仅检测 `is_set`（是否已设置），不回显密钥 |
| 模型选择格式 | `modelId (providerName)` 格式展示，支持搜索/过滤 |
| 端点状态展示 | 清晰区分 `configured`（已配置内置提供商）和 `custom`（自定义端点） |

### 3.3 Open WebUI（Python + Svelte）— 行业标杆

**设计哲学**: 运行时动态发现 + 数据库自定义模型覆盖（Dynamic Discovery + DB Override）

| 特性 | 实现方式 |
|------|---------|
| **模型动态发现** | 从已配置的 OpenAI 兼容端点和 Ollama 实例运行时拉取模型列表，代码中**无硬编码模型 ID** |
| **自定义模型覆盖** | 数据库 `model` 表存储用户自定义模型：可覆盖现有模型（同 ID）或创建新模型（不同 `base_model_id`） |
| **Provider 配置** | `OPENAI_API_BASE_URLS[]` + `OPENAI_API_KEYS[]`（多端点）；`OLLAMA_BASE_URLS[]`（多实例） |
| **配置持久化** | `PersistentConfig` 模式：环境变量为默认值，数据库配置覆盖生效，管理界面修改后持久化到数据库 |
| **模型元数据** | `params`（技术参数）和 `meta`（显示元数据：`profile_image_url`、`description`、`capabilities`、`tags`）分离 |
| **访问控制** | 基于 `access_grants` 的细粒度模型权限控制（多用户场景） |
| **模型标签** | 模型可加 `tags` 进行分类和过滤 |
| **Function/Pipe** | 模型可关联自定义函数或管道处理 |
| **缓存** | `MODELS_CACHE_TTL` 控制模型列表缓存时长 |
| **Arena 模型** | 支持对比评测 Arena 模型配置 |
| **筛选** | `get_filtered_models()` 基于用户权限和配置过滤模型列表 |

### 3.4 对标结论：关键设计启示

| # | 启示 | UI_REF 来源 | 我们的现状 |
|---|------|------------|-----------|
| 1 | **模型数据应动态发现，而非硬编码** | Open WebUI | ALL_MODEL_CONFIGS 硬编码 38+ 模型 |
| 2 | **Provider 配置（baseUrl+apiKey）与模型定义分离** | 三者一致 | 耦合在 ModelConfigs.ts 中 |
| 3 | **用户可维护的配置文件 / UI** | OpenClaw + Open WebUI | 仅 CLI /model 命令，无管理 UI |
| 4 | **自定义模型覆盖（base model override）** | Open WebUI | 不支持 |
| 5 | **Provider CRUD（创建/编辑/删除）** | OpenClaw | 不支持 |
| 6 | **配置变更预览 + 自动同步引用** | OpenClaw | 无 |
| 7 | **凭据安全处理（不回显，仅检测 is_set）** | OpenClaw + Hermes | API Key 明文处理 |
| 8 | **模型标签/分类/过滤** | Open WebUI | 无 |
| 9 | **供应商预设快速配置** | OpenClaw | 无 |
| 10 | **多端点支持（多 OpenAI URL、多 Ollama 实例）** | Open WebUI | 单端点 |

## 四、发现问题（新增对标视角）

### P0 - 数据全部硬编码在源代码中

**严重程度: 最高**。这是整个系统的架构性缺陷。

当前 38+ 个模型、所有定价、能力信息全部写死在 `ModelConfigs.ts` 中。这导致：
- 新增/更新模型需要修改源代码 + 重新部署
- 用户无法自行添加本地模型（Ollama）或自定义端点（Azure）
- 定价更新依赖于发版节奏，无法动态调整

**对标行业实践**:
- Open WebUI: **零硬编码模型 ID**，全部运行时发现
- OpenClaw-Admin: 模型配置在配置文件中（YAML/JSON），用户可编辑
- Hermes: 通过端点发现，无硬编码模型

### P0 - 定价数据三处散布且不一致

| 位置 | 字段 | 覆盖模型数 | 是否含缓存定价 |
|------|------|-----------|--------------|
| `ModelConfigs.ts:ALL_MODEL_CONFIGS[].pricing` | `inputPer1M, outputPer1M` | 38+ | ❌ 缺 cache 字段 |
| `cost/ModelPricing.ts:MODEL_PRICING` | 完整 5 字段 | ~30 | ✅ |
| `core/tokenBudget/providers/BuiltinPriceProvider.ts` | 完整 5 字段 | ~30 | ✅ |

### P0 - 模型能力定义两处重复

| 位置 | 形式 |
|------|------|
| `ModelConfigs.ts` 每个配置的 `capabilities` 字段 | 数组枚举值 |
| `models/types.ts:MODEL_CAPABILITIES` | 模型名 → 能力数组的映射 |

### P1 - 客户端模型管理功能严重不足

| 维度 | 现状 | OpenClaw 对标 |
|------|------|--------------|
| 模型列表 | 仅 CLI 文本输出 | 数据表格，按 Provider 分组 |
| Provider 管理 | 不支持 | 创建/编辑/删除 Provider |
| 快速预设 | 不支持 | 内置 4 家国内厂商一键配置 |
| 变更预览 | 不支持 | 保存前 diff 预览 + 自动同步 |
| 模型测试 | 不支持 | 可通过 API 测试连接 |
| 凭据安全 | 明文传输 | API Key 显示 `********` |

### P1 - `model-picker.ts` 独立硬编码模型目录

[model-picker.ts](file:///E:/PY/CODES/PY_APP/app/src/core/flows/model-picker.ts) 维护了一套独立的 12 个模型硬编码列表，与 `ALL_MODEL_CONFIGS` 完全脱节：
- 模型版本过时（如 `claude-sonnet-4-20250514` 而非 `claude-sonnet-4-6`）
- 缺少定价信息和 `capabilities` 枚举
- 需手工同步，极易遗漏

### P1 - 废弃模块未清理

- `ai/catalog/index.ts`: 标注 `@deprecated` 但未清理
- `utils/model/model.ts`: 硬编码返回 `gpt-4`

### P1 - Rust 端模型列表严重过时

[model.rs](file:///E:/PY/CODES/PY_APP/client/src-tauri/src/commands/model.rs) 仅列出 3 个模型（`gpt-4`、`gpt-3.5-turbo`、`claude-3`），全部为过时 ID。

### P2 - 模型选择策略 Anthropic 中心化

`ModelManager` 的 `getDefaultMainLoopModel()` 逻辑完全围绕 Anthropic 订阅层级设计，对 OpenAI/DeepSeek/Google 等提供商用户无意义。

### P2 - `[1m]` 后缀运行时处理增加复杂度

运行时修改模型字符串，API 调用时又去除，应该通过配置声明。

### P2 - 缺少动态模型注册/发现机制

Ollama 本地模型、Azure 自定义部署等场景无法在运行时注册。

## 六、优化建议

### 6.1 模型数据从代码硬编码迁移到配置文件（P0）

这是最核心的架构变更：**模型数据严禁写死在代码中**。

#### 目标架构

```
                    ┌─────────────────────────┐
                    │  配置文件（用户可维护）    │
                    │  ~/.pyapp/models.yaml     │
                    │  ~/.pyapp/providers.yaml  │
                    └──────────┬──────────────┘
                               │ 加载
                    ┌──────────▼──────────────┐
                    │  运行时模型注册表          │
                    │  ModelRegistry (新)       │
                    │  - 默认内置模型（编译时）   │
                    │  - 用户配置模型（覆盖）     │
                    │  - 动态发现模型（Ollama等） │
                    └──────────┬──────────────┘
                               │ 查询
                    ┌──────────▼──────────────┐
                    │  ModelManager            │
                    │  （保持现有 API 不变）     │
                    └─────────────────────────┘
```

#### 配置文件格式设计

借鉴 OpenClaw-Admin 的配置结构和 Open WebUI 的 Provider 设计：

**`~/.pyapp/providers.yaml`** — Provider 配置（用户维护）

```yaml
# 模型提供商配置
providers:
  # OpenAI 兼容端点
  openai:
    api: openai-completions
    baseUrl: https://api.openai.com/v1
    apiKey: sk-xxx
    # 模型白名单（不填则自动发现全部）
    models:
      - gpt-4o
      - gpt-4o-mini
      - gpt-4-turbo

  # Anthropic
  anthropic:
    api: anthropic-messages
    baseUrl: https://api.anthropic.com
    apiKey: sk-ant-xxx
    models:
      - claude-sonnet-4-6
      - claude-opus-4-6

  # Ollama 本地
  ollama:
    api: openai-completions
    baseUrl: http://localhost:11434/v1
    # 不指定 models，运行时自动发现

  # Azure OpenAI
  azure-openai:
    api: openai-completions
    baseUrl: https://xxx.openai.azure.com
    apiKey: azure-xxx
    models:
      - gpt-4o
      - gpt-35-turbo

  # DeepSeek
  deepseek:
    api: openai-completions
    baseUrl: https://api.deepseek.com
    apiKey: sk-xxx
    models:
      - deepseek-chat
      - deepseek-reasoner
```

**`~/.pyapp/models.yaml`** — 模型覆盖配置（可选，用户维护）

```yaml
# 模型显示名称覆盖/自定义模型
models:
  claude-sonnet-4-6:
    displayName: "我的 Sonnet"
    contextWindow: 200000
    maxOutputTokens: 16384
    capabilities: [streaming, vision, thinking]
    pricing:
      inputPer1M: 3
      outputPer1M: 15

  # 自定义模型（基于 base_model_id）
  my-custom-model:
    baseModel: gpt-4o
    displayName: "自定义模型"
    contextWindow: 128000
```

#### ModelRegistry 新组件

```typescript
class ModelRegistry {
  private builtinModels: Map<string, ModelConfig>;  // 编译时内置（ModelConfigs.ts 降级为内置默认值）
  private userModels: Map<string, ModelConfig>;      // 从配置文件加载
  private discoveredModels: Map<string, ModelConfig>; // 运行时发现（Ollama 等）

  // 加载顺序：内置 → 配置文件覆盖 → 运行时发现追加
  async load(): Promise<void>;

  // 支持热重载
  async reload(): Promise<void>;
}
```

#### 实施步骤

1. **ModelConfigs.ts 降级为内置默认值**（不再作为唯一数据源，降级为后备）
2. **实现 YAML 配置文件加载器**（`~/.pyapp/providers.yaml` + `~/.pyapp/models.yaml`）
3. **实现 ModelRegistry**（内存注册表，用户配置覆盖内置默认值）
4. **Provider 配置接入**：各 Provider 从配置读取 baseUrl/apiKey，不再硬编码
5. **添加 `--model-config` / `--provider-config` CLI 参数**支持指定配置文件路径
6. **用户界面**：客户端提供配置编辑页面

4. 删除 `core/tokenBudget/providers/BuiltinPriceProvider.ts`

### 6.3 能力定义收敛（P0）

**方案**: 删除 `models/types.ts` 中的 `MODEL_CAPABILITIES` 映射，统一使用 `ModelConfig.capabilities`。

### 6.4 废弃模块清理（P1）

按第五章横切清单执行。

### 6.5 模型选择策略抽象（P2）

将模型选择逻辑从 `ModelManager` 解耦为策略模式：

```typescript
interface ModelSelectionStrategy {
  getDefaultModel(config: ModelManagerConfig): string;
  getFallbackModel(config: ModelManagerConfig): string;
}

class AnthropicSelectionStrategy implements ModelSelectionStrategy { ... }
class OpenAISelectionStrategy implements ModelSelectionStrategy { ... }
class DeepSeekSelectionStrategy implements ModelSelectionStrategy { ... }
```

根据 `config.provider` 自动选择策略。

### 6.6 上下文窗口扩展规范化（P2）

移除 `[1m]` 后缀的运行时处理，改为配置声明：

```typescript
interface ModelConfig {
  extendedContextWindows?: Array<{
    suffix: string;      // 如 '1m'
    windowSize: number;  // 如 1000000
  }>;
}
```

### 6.7 动态模型注册机制（P2）

```typescript
class ModelManager {

   * 运行时注册自定义模型（用于 Ollama、Azure 自定义部署等）

  /**
   * 从配置文件加载用户自定义模型
```
