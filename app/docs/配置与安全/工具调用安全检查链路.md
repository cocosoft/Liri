# 工具调用安全检查链路（契约）

> **本文目的**：固化「一次工具调用从发起 → 权限判定 → 审批 → 安全分析 → 沙箱执行」的**逐跳链路**，并明确每一层
> **「谁能裁决（可阻断）/ 谁只读（仅观测）」**，消除"以为有门其实没有"的歧义。
>
> **事实源**：本文以**代码**为准，每跳附 `file:line`（行号基线 **2026-10-06** 全链复核；
> **2026-10-07 局部更新**：新增「非幂等重试闸（R07-3）」一层 ⇒ §1.1 链路图 / §2 / §5 相应行号已同步）。
> 规则**细节**（角色/规则配置、沙箱路径白名单语义）仍以 [权限系统](permissions.md) · [沙箱安全](sandbox.md) 与对应代码为准；
> 本文只固定**链路结构与各层职责**，不重复规则定义。
>
> **维护约定**：改动链路（新增/移除一层、改变默认行为、新增旁路）**必须同步本文**，否则视为文档失同步。

## 1. 总览：存在两条执行路径

| 路径 | 入口 | 是否有权限门 | 说明 |
|------|------|:------------:|------|
| **主 Agent 路径**（对话/流式） | `ReActToolLoop.act` → `ChatManager.executeTool` → `ToolExecutionService.execute` | ✅ **有** | 唯一经过 `PermissionManager` 的路径 |
| **HTTP / CoreAPI 旁路** | `CoreAPIImpl.executeTool` → `ToolManager.executeTool` | ❌ **无** | 只有 shield 屏蔽 + 工具禁用 + 策略管线（默认策略恒 allow） |

> ⚠️ 这是本链路**最重要的一条事实**：`app/src/tools/ToolManager.ts:334-394` 的 `executeTool` **不调用** `PermissionManager`
> （见 §4-①）。两条收口的存在与边界由 `app/src/tools/shieldGuard.ts:25-33` 自述。

## 3. 决策点细节

### 3.1 权限模式分派（`PermissionManager.checkPermissionInner:288-329`）

| 模式 | 行为 | 代码 |
|------|------|------|
| `bypass` | **无条件放行**（不查 killswitch） | `:488-490` `createAllowDecision('Bypassing permissions check')` |
| `dontAsk` / `ask` / `alwaysAsk` | 不询问/恒询问 | `:499-551` |
| `auto` | 分类器判定；**分类器异常 ⇒ 放行（fail-open）** | `:678-762`，catch 分支 `:759-760` |
| `default` | 规则链：安全白名单 → deny 规则 → 细粒度角色 deny → 命令黑白名单 → ask 规则 → allow 规则 → 内容级 → **默认行为** | `:561-652` |
| **默认行为**（无规则匹配） | `defaultBehavior` 缺省 **`'allow'`**（`PERMISSION_DEFAULT_BEHAVIOR=deny` 可收窄为 fail-closed） | 字段 `:83` · 读取 `:149-152` · 落点 `:648-651` |

### 3.2 沙箱门控（`decideBashLandlockGate:221-265`）

| 输入状态 | 结果 | 说明 |
|----------|------|------|
| `config.enabled === false` | `plain`（master-off） | `:230` |
| 评测期强制（`LIRI_EVAL_BASH_LANDLOCK`）且 Linux+能力可用 | `landlock`（eval-forced） | `:233-236` |
| 评测期强制但能力不可用 | `plain`（eval-forced-fallback） | `:237`（**不 refuse**，避免打断评测） |
| `bashEnabled === false`（**默认**） | `plain`（switch-off） | `:240` |
| `bashEnabled === true` 但平台不是 Linux | **`refuse`** | `:242-251` fail-closed |
| `bashEnabled === true` 但能力不可用 | **`refuse`** | `:253-262` fail-closed |

默认值（`sandbox/landlock/config.ts:70-75`）：`enabled: true` · `failClosed: false` · `bashEnabled: false`。
⇒ **开箱状态下 bash 不做内核级限制**，「开启即真受限」是**显式选择**的语义。

## 6. 变更本链路时的自检清单

1. **改了默认值**（如 `defaultBehavior`、`bashEnabled`、`autoAllowIfSandboxed`）⇒ 必须同步 §3、§4 与 `permissions.md` / `sandbox.md`。
2. **新增执行路径**（绕过 `ToolExecutionService`）⇒ 必须回答"权限门在哪"；若无门，按 §4-① 的同口径如实登记，**不得**默认为有门。
3. **新增可裁决层** ⇒ 必须在 §5 注明"可裁决"并提供**命中即拒绝**的证据（含 fail-closed 与否）。
4. **新增降级/回退** ⇒ 必须同时给出**留痕**（日志/事件），遵循 CS03-002「回退不得掩盖错误」。
5. **本文与代码冲突时以代码为准**，并立即修正本文（含行号）。
