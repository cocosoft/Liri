## 一、任务调度引擎（TAORLoop + PDCA）

### 引擎架构

```
ChatManager / PDCA
    │
    ▼
TAORLoop ──▶ _runModern()    ← 统一编排核心
    │              │
    │    ┌─────────┼──────────┐
    │    ▼         ▼          ▼
    │ THINK ──▶ ACT ──▶ OBSERVE ──▶ (loop)
    │    │         │           │
    │    │   LoopDetector   CircuitBreaker
    │    │   PathGuard      ErrorRecovery
    │    │   FileIOLoopD.    DailyBudget
    │    │   VerifierAgent  RunLogger
    │    ▼
    │ COMPLETED / ABORTED / ERROR
    │
    ▼
LongRunningTaskOrchestrator (PDCA: Plan→Execute→Review→Decide)
    │
    ├─ LifecycleTracker (内存事件历史)
    ├─ AuditReport (结构化审计报告)
    ├─ FileLockManager (文件级并发锁)
    └─ VerifierAgent (双指标验证)
```

## 三、回滚能力

### ✅ 检查点回滚（TAOR级别）

```
saveCheckpoint() → 写.tmp → fsync → rename .json
resumeFromCheckpoint() → 读取JSON → 恢复:
  turnCount, phase, tokenBudget, conversationSummary
  circuitBreaker, loopDetector, errorRecovery state
  inboxState(待审批项恢复)
```

三种检查点类型：
- auto — 每N轮自动保存(默认5轮)
- manual — 手动触发
- before_abort — 中止前自动保存

### ✅ 会话级别回滚

SessionStore(FileSystemStorage)支持：
- 归档 → SessionArchiver.archiveSession()
- 恢复 → SessionArchiver.restoreSession()
- 修剪 → SessionPruner

### 🟡 回滚限制（**状态：未验证** — 不得作为结论引用）

> ⚠️ **2026-09-12 复核**：以下三条**本轮未经验证**，且它们源自本文自身（本文已被证实有 4 条论断失准），
> 按《Liri 缺陷查补计划》D7 的纪律：**未验证前不得据此分配工作量**。
> 核实方法（客观判据，替代读代码猜语义）：① 造写操作 → 回滚 → **比对回滚前后环境终态**；
> ② 构造 approve → 撤销 → 断言状态机终态；③ 记录写前文件哈希 → 回滚 → 断言哈希还原。

1. **（未验证）无完整快照回滚** — checkpoint只保存状态摘要，不保存完整消息历史
2. **（未验证）PDCA的Decide不支持UNDO** — approve后无法撤销
3. **（未验证）文件操作不可回滚** — file_write等操作不可逆
