# 设计理念

## 核心原则

### 1. 最小惊讶原则

系统的行为应该符合用户的直觉预期：

- 命令语法保持一致
- 错误信息清晰可理解
- 默认配置安全合理

### 2. 渐进式复杂度

用户可以按需深入：

- 新手：基本命令即可完成工作
- 进阶：可使用技能和配置文件
- 专家：可开发插件扩展功能

### 3. 安全默认

所有功能默认采用安全配置：

- 文件操作限制在允许目录
- 命令执行需要权限验证
- 敏感信息自动脱敏

### 4. 模块化设计

功能以独立模块组织：

- 每个模块有明确的职责边界
- 通过接口而非具体实现耦合
- 支持独立测试和替换

## 设计决策

### 为什么选择 TypeScript？

- 类型安全减少运行时错误
- 丰富的类型系统支持复杂数据建模
- 庞大的生态系统

### 为什么使用 Bun？

- 内置测试运行器
- 快速的包管理器
- TypeScript 原生支持

### 为什么使用 Rust 编写原生模块？

- 性能关键任务（如 AST 解析）
- 安全的系统调用封装
- 跨平台兼容性
