## 总体评估：5/10 分

"项目"模块的混乱根源是**两套互相隔离的"项目"体系并行存在**，且其中一套是"半成品"（内存态 + 硬编码模板）。用户从不同入口进入，看到的"项目"完全不是同一个东西，数据不互通。

> 修复状态: 待实施（建议按下方阶段一 → 阶段五 推进）

## 一、架构现状：双系统并存

```
体系 A（worktrees 后端持久化）                    体系 B（projectStore 纯内存）
┌──────────────────────────────┐                ┌──────────────────────────────┐
│ /projects → ProjectsPage     │                │ /work → /workspace/default/work│
│   ↓ 过滤 workspaceSource=user│                │   ↓ WorkPageLayout（三栏）    │
│ /workspace/:id → ProjectView │                │     ↓ Tab「项目」            │
│   = 会话侧栏 + 聊天区          │                │   WorkBoardView projectId="default"│
│   （首次进入自动建"对话 1"）   │                │     ↓ projectDecomposer      │
│ 数据: root-store worktrees   │                │   （硬编码电网模板分解）      │
│       + sessions（后端 API）  │                │ 数据: projectStore（zustand  │
│                              │                │       内存，刷新即丢）        │
└──────────────────────────────┘                └──────────────────────────┘
        互不可见 · 互不联动 · 入口互相打架
```

**体系 A 实际是"带项目名外壳的聊天会话"**；**体系 B 才有"项目分解/看板"的实质功能**，但被硬编码锁死在 "default" 上且不持久化。

---

## 二、问题清单

### 🔴 P1. 两套"项目"体系并行，数据完全隔离

**文件**:
- 体系 A: `components/views/ProjectsPage.tsx` + `components/Workspace/ProjectView.tsx` + `stores/root-store/workspaceSlice.ts`
- 体系 B: `components/Workspace/WorkContentArea.tsx` (L172) + `components/Workspace/WorkBoardView.tsx` + `stores/projectStore.ts`

**问题**: 在 `/projects` 新建的项目（worktree），在 `/workspace/:id/work` 的"项目"Tab 中完全不可见；反之在"项目"Tab 导入需求分解出的工作项，也不会出现在 `/projects` 列表里。两个入口展示两种"项目"，用户无法理解。

---

### 🔴 P2. `projectId="default"` 硬编码，所有工作空间共享同一个项目

**文件**:
- `components/Workspace/WorkContentArea.tsx` L172: `<WorkBoardView projectId="default" />`
- `components/Workspace/WorkBoardView.tsx` L762: `importNodesDirect("default", ...)` — workspaceId 也写死

**问题**: 无论当前在哪个工作空间/项目，看板永远读写同一个 `projectId="default"` 的内存项目。切换工作空间，项目看板内容不变；且没有任何 UI 可以创建第二个项目（`projectStore.createProject` 是死代码，0 个调用者）。

---

### 🔴 P3. `projectDecomposer` 是硬编码电网模板，不是"AI 分解"

**文件**: `services/projectDecomposer.ts`（全文 ~300 行）

**问题**: `decompose()` 无视用户粘贴的需求内容，几乎恒定返回一套电网"流程监控看板"模板节点：
- "流程数据接入层搭建" / "流程穿式监控大看板框架"（永远存在）
- "采购全流程时长预警场景"（永远存在）
- "智慧两票 / 特高压 / 第一议题 / 花钱问效"（按关键词追加）
- "AI 异常诊断与智能体能力"（永远存在）

`hasScene()` 只是判断是否在模板上追加场景，即使关键词完全不匹配也返回 4+ 个固定顶层节点。UI 文案写着"AI 将自动分解为工作项网络"，实际是死模板；与后端 `workspaceService.createProject` API 也完全脱节。

---

### 🟡 P4. `projectStore` 纯内存不持久化，`createProject` 是死代码

**文件**: `stores/projectStore.ts`

**问题**:
- 所有项目/节点只存在 zustand 内存中，刷新页面全部丢失；而体系 A 的数据走后端 API，生命周期不一致。
- `createProject` action 定义后无任何组件调用（grep 确认仅 WorkBoardView 的 `importNodesDirect` 会创建项目）。
- `recalculateProgress` 会把 `progress===0` 的项目整体状态置为 `planning`，与 `importNodesDirect`  `status:"active"` 互相矛盾（初次导入后一调用进度重算就被打回 planning）。

---

### 🟡 P5. `/work` 路由硬编码 `default` 工作空间

**文件**: `routes/index.tsx` L255: `{ path: "/work", element: <Navigate to="/workspace/default/work" replace /> }`

**问题**: 点击"工作"入口永远进入 `default` 空间，与当前项目/最近项目无关。而体系 A 的入口都是 `/workspace/:`，`/work` 与其语义割裂，用户从"项目"进入工作台看到的是另一个世界的空壳。

### 🟡 P6. 项目列表页把"默认工作空间"当项目展示

**问题**: `ProjectsPage` 过滤 `workspaceSource === "user"`，而 App 首次启动自动创建的 `createWorktree({ name: "默认工作空间", path: "." })` 默认 source 就是 `"user"` → **"默认工作空间"会出现在项目列表中**，名称/路径都不像项目，且无法删除（`deleteWorktree` 仅禁止删除 system 源）。

## 三、优化建议

### 阶段一：统一数据模型（根治，P1/P4/P9）

1. **唯一项目实体 = worktree**（后端持久化）。`/projects` 与工作台读同一份 `worktrees`。
2. **Project/ProjectNode 挂到 worktree 上**（或后端 projectId 与 worktreeId 一一对应），废弃独立 `projectStore.projects` 表；打通 `workspaceService.createProject`，前端改调后端 API 持久化。
3. 删除死代码 `projectStore.createProject` / 未调用的后端接口，或补齐调用链。

### 阶段二：统一路由与入口（P5/P7/P10）

4. **点击项目 → 进入工作台** `/workspace/:id/work`（三栏：文件树/看板/对话），不再进裸聊天视图。
5 `ProjectView`（聊天视图）降级为工作台内的一个 Tab（对话），或迁移到 `/workspace/:id/chat`。
6. `/work` 重定向改为携带当前 worktreeId：`/workspace/${currentWorktreeId}/work`。
7. 侧栏用户项目按钮与"项目"按钮行为统一：前者跳 `/workspace/:id/work`，后者保持列表页。

### 阶段三：去硬编码（P2/P8）

8. `WorkBoardView` 的 `projectId` 由 URL/当前 worktree 派生，删除 `"default"`；`importNodesDirect` 的 workspaceId 同样从上下文取。
9. 每个项目进入时若无 Project 则自动创建空项目（复用 `createProject`），保证看板可空态展示而非硬编码 default。
10. 工作台文件树读取 `worktree.path` 真实目录，替代 `"."`。

### 阶段四：真正的 AI 分解（P3）

11. `projectDecomposer` 改为调用后端 LLM/agent 完成需求分解（需求文本 → 结构化工作项），移除硬编码电网模板；电网模板降级为"示例数据/离线兜底"。
12. 分解结果写入后端（阶段一的 createProject API），并支持重新分解、编辑节点。

### 阶段五：体验补全（P6/P11）

13. App 启动的"默认工作空间"改为 `workspaceSource:"system"`，或创建后不进入项目列表；列表页补充进度/工作项数/更新时间。
14. 合并 `CreateProjectModal` 与 `WorkspaceSwitcher` 为一个表单组件，统一"名称 + 路径 + 描述 + 创建后跳转"行为。
15. 删除项目时同步清理后端 project 数据（deleteWorktree 已清理会话，需补 project 清理）。
