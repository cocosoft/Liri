## 一、总路线图

```
P0 ─── 消除架构双轨制 ─── 第 1~2 周
 │
 ├── P1a ─── 架构护栏加固 ─── 第 1 周（与 P0 并行）
 │
 ├── P1b ─── 类型体系治理 ─── 第 2~3 周
 │
 ├── P1c ─── 测试覆盖提升 ─── 第 2~4 周（与 P1b 并行）
 │
 ├── P2a ─── 基础设施优化 ─── 第 3~5 周
 │
 └── P3 ─── CI 完善 + 持续治理 ─── 全程穿插
```

**关键原则**：
- 每步可验证（验收标准明确）
- 灰度回退（核心变更需带 feature flag）
- 测试先行（重构前确保已有测试通过）
- 异常值优先处理（先解决阻路问题，再优化非关键项）

## 二、任务分级说明

### 优先级定义

| 级别 | 定义 | 处理时限 |
|:----:|------|---------|
| **P0** | 阻碍其他优化的架构问题（双轨制） | 立即，1~2 周内完成 |
| **P1** | 核心架构能力缺失（约束/类型/测试） | 4 周内完成 |
| **P2** | 基础设施优化（性能/可维护性） | 8 周内完成 |
| **P3** | 持续改进项（CI/健康度） | 无硬时限，穿插执行 |

### 依赖关系

```
P0 统一 DI → P1c DIContainer 测试（需等 P0 稳定）
P0 统一插件 → P2a 启动管道重构（需等 DI+Plugins 统一）
P1a 分层约束 → 所有后续重构的安全护栏
P1b 类型出口 → 后续模块重构时引用路径一致
P2a 状态机 → 需等 P1c 的 StateMachine 测试通过
P2a Config 简化 → 需等 P1a 分层约束就绪
```
