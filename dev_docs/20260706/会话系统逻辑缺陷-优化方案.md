## 2. 修复方案

### 2.1 BUG-01 — getMessages 静默失败 + 过早返回

**文件**：[`CombinedSessionGateway.ts`](file:///E:/PY/CODES/PY_APP/app/src/session/gateway/CombinedSessionGateway.ts)

**问题**：`catch {}` 静默吞掉所有异常，无法区分"session 不存在"和"系统错误"。

**方案**：

```typescript
// 遍历 gateways 时的错误处理改进
for (const { gateway, agentId } of activeEntries) {
  try {
    const messages = await gateway.getMessages(sessionId, options);
    if (messages.length > 0) return messages;
  } catch (err) {
    // 区分"session 不存在"（预期行为）和"系统错误"（需记录）
    if (isSessionNotFoundError(err)) {
      // session 不在此 gateway，尝试下一个 — 正常流程
      continue;
    }
    // 系统级错误（IO、网络等）— 记录日志
    logger.warn(`Gateway ${agentId} getMessages 失败`, {
      sessionId,
      agentId,
      error: err instanceof Error ? err.message : String(err),
    });
    // 不继续尝试其他 gateway，因为不是"不存在"而是"出错了"
    throw err;
  }
}
return [];
```

**需新增**：`isSessionNotFoundError()` 辅助函数，检查错误是否为 `SessionNotFoundError` 类型。

### 2.2 BUG-02 — getSessionStats 硬编码 0

**文件**：[`CombinedSessionGateway.ts`](file:///E:/PY/CODES/PY_APP/app/src/session/gateway/CombinedSessionGateway.ts)

**问题**：`activeSessions` 和 `archivedSessions` 硬编码为 0，统计数据无效。

**方案**：从各子 gateway 聚合真实值。

```typescript
// 遍历所有 gateway 聚合统计
let activeSessions = 0;
let archivedSessions = 0;

for (const { gateway } of activeEntries) {
  try {
    const stats = await gateway.getSessionStats();
    activeSessions += stats.activeSessions;
    archivedSessions += stats.archivedSessions;
    totalSessions += stats.totalSessions;
    totalDuration += stats.averageSessionDuration * stats.totalSessions;
    totalMessages += stats.totalMessages;
  } catch (err) {
    logger.warn(`Gateway stats 获取失败`, {
      error: err instanceof Error ? err.message : String(err),
    });
  }
}

return {
  totalSessions,
  activeSessions,
  archivedSessions,
  averageSessionDuration: totalSessions > 0 ? totalDuration / totalSessions : 0,
  totalMessages,
};
```

### 2.3 BUG-03 — SessionLock 崩溃后死锁

**文件**：[`SessionLock.ts`](file:///E:/PY/CODES/PY_APP/app/src/session/lock/SessionLock.ts)

**问题**：文件锁在进程崩溃后无法清理，导致永久死锁。无锁过期/超时机制。

**方案**：增加锁超时 + 强制获取机制。

```typescript
export interface SessionLockOptions {
  /** 锁文件路径 */
  lockPath: string;
  /** 锁超时时间（毫秒），超过此时间的锁视为过期，可被强制获取 */
  lockTimeoutMs?: number;
  /** 获取锁的最大等待时间（毫秒） */
  acquireTimeoutMs?: number;
}

const DEFAULT_LOCK_TIMEOUT_MS = 30_000;   // 30 秒锁自动过期
const DEFAULT_ACQUIRE_TIMEOUT_MS = 10_000; // 10 秒内尝试获取

export class SessionLock {
  private lockPath: string;
  private lockTimeoutMs: number;
  private acquireTimeoutMs: number;
  private acquired: boolean = false;

  constructor(options: SessionLockOptions) {
    this.lockPath = options.lockPath;
    this.lockTimeoutMs = options.lockTimeoutMs ?? DEFAULT_LOCK_TIMEOUT_MS;
    this.acquireTimeoutMs = options.acquireTimeoutMs ?? DEFAULT_ACQUIRE_TIMEOUT_MS;
  }

  async acquire(): Promise<boolean> {
    const startTime = Date.now();

    while (Date.now() - startTime < this.acquireTimeoutMs) {
      try {
        // 检查是否已有锁文件
        if (fs.existsSync(this.lockPath)) {
          const stat = fs.statSync(this.lockPath);
          const lockAge = Date.now() - stat.mtimeMs;

          // 锁已过期 → 强制清理
          if (lockAge > this.lockTimeoutMs) {
            logger.warn('检测到过期锁，强制清理', {
              lockPath: this.lockPath,
              lockAgeMs: lockAge,
              lockTimeoutMs: this.lockTimeoutMs,
            });
            fs.unlinkSync(this.lockPath);
          } else {
            // 锁未过期 → 等待
            await new Promise((r) => setTimeout(r, 100));
            continue;
          }
        }

        // 创建锁文件（写入进程 PID 和时间戳用于诊断）
        fs.writeFileSync(this.lockPath, JSON.stringify({
          pid: process.pid,
          acquiredAt: new Date().toISOString(),
        }), { flag: 'wx' }); // 'wx' = 排他创建，文件已存在则失败

        this.acquired = true;
        return true;
      } catch (err) {
        // 文件已存在（并发竞争失败）→ 重试
        if ((err as NodeJS.ErrnoException).code === 'EEXIST') {
          await new Promise((r) => setTimeout(r, 100));
          continue;
        }
        throw err;
      }
    }

    logger.error('获取会话锁超时', {
      lockPath: this.lockPath,
      acquireTimeoutMs: this.acquireTimeoutMs,
    });
    return false;
  }

  async release(): Promise<void> {
    if (!this.acquired) return;
    try {
      if (fs.existsSync(this.lockPath)) {
        fs.unlinkSync(this.lockPath);
      }
    } catch (err) {
      logger.warn('释放会话锁失败', {
        lockPath: this.lockPath,
        error: err instanceof Error ? err.message : String(err),
      });
    } finally {
      this.acquired = false;
    }
  }
}
```

**关键改进**：
- 锁文件写入 PID + 时间戳，便于诊断
- `lockTimeoutMs`（默认 30s）：超过此时间的锁视为过期，自动清理
- `acquireTimeoutMs`（默认 10s）：避免无限等待
- 使用 `flag: 'wx'` 排他创建，防止并发竞争

### 2.4 BUG-04 — SessionStore 并发写覆盖

**文件**：[`SessionStore.ts`](file:///E:/PY/CODES/PY_APP/app/src/session/storage/SessionStore.ts)

**问题**：文件存储模式下，并发 `getSession → 修改 → setSession` 导致后写覆盖先写，数据丢失。

**方案**：在 `updateSession` 级别集成 `SessionLock`，确保同一 session 的读-改-写串行化。

```typescript
async updateSession(
  sessionId: string,
  updater: (session: Session) => Session
): Promise<Session> {
  const lock = new SessionLock({
    lockPath: path.join(this.lockDir, `${sessionId}.lock`),
  });

  const acquired = await lock.acquire();
  if (!acquired) {
    throw new AppError(
      `无法获取会话锁: ${sessionId}`,
      'SESSION_LOCK_TIMEOUT'
    );
  }

  try {
    // 在锁保护下执行读-改-写
    const session = await this.getSession(sessionId);
    if (!session) {
      throw new AppError(`会话不存在: ${sessionId}`, 'SESSION_NOT_FOUND');
    }

    const updated = updater(session);
    await this.setSession(updated);
    return updated;
  } finally {
    await lock.release();
  }
}
```

> **注意**：需确认 `SessionStore` 已有 `lockDir` 配置。若没有，需新增或用临时目录。

### 2.5 BUG-05 — SessionGateway.initialize() 非原子双重检查

**文件**：[`SessionGateway.ts`](file:///E:/PY/CODES/PY_APP/app/src/session/SessionGateway.ts)

**问题**：`if (this.initialized) return` 不是原子操作，并发调用会重复初始化。

**方案**：使用 Promise 缓存实现单次初始化。

```typescript
private initPromise: Promise<void> | null = null;

async initialize(): Promise<void> {
  // 已初始化 → 直接返回
  if (this.initialized) return;

  // 正在初始化 → 等待同一个 Promise
  if (this.initPromise) {
    return this.initPromise;
  }

  // 首次初始化
  this.initPromise = this._doInitialize();
  try {
    await this.initPromise;
    this.initialized = true;
  } finally {
    this.initPromise = null;
  }
}

private async _doInitialize(): Promise<void> {
  // 实际的初始化逻辑
  await this.storage.initialize();
  await this.loadSessions();
  // ...
}
```

### 2.6 BUG-06 — CombinedSessionGateway 无路由表

**文件**：[`CombinedSessionGateway.ts`](file:///E:/PY/CODES/PY_APP/app/src/session/gateway/CombinedSessionGateway.ts)

**问题**：不指定 `agentId` 时逐一遍历所有 gateway 尝试发送，低效且可能产生重复副作用。

**方案**：维护 session → gateway 的路由缓存。

```typescript
// sessionId → agentId 路由缓存
private sessionRouteCache = new Map<string, string>();

async sendMessage(
  content: string,
  options?: { sessionId?: string; agentId?: string }
): Promise<Message> {
  const { sessionId, agentId } = options ?? {};

  // 指定了 agentId → 直接路由
  if (agentId) {
    const entry = this.activeGateways.get(agentId);
    if (!entry) throw new AppError(`Gateway ${agentId} 不存在`, 'GATEWAY_NOT_FOUND');
    return entry.gateway.sendMessage(content, options);
  }

  // 从缓存查找路由
  const cachedAgentId = sessionId ? this.sessionRouteCache.get(sessionId) : undefined;
  if (cachedAgentId) {
    const entry = this.activeGateways.get(cachedAgentId);
    if (entry) {
      try {
        return await entry.gateway.sendMessage(content, options);
      } catch (err) {
        // 缓存可能过期，清除后走遍历逻辑
        if (sessionId) this.sessionRouteCache.delete(sessionId);
      }
    }
  }

  // 回退：遍历查找（首次或缓存失效时）
  for (const [id, { gateway }] of this.activeGateways) {
    try {
      const result = await gateway.sendMessage(content, options);
      // 路由成功 → 缓存
      if (sessionId) this.sessionRouteCache.set(sessionId, id);
      return result;
    } catch (err) {
      if (isSessionNotFoundError(err)) continue;
      throw err;
    }
  }

  throw new AppError('未找到匹配的 Gateway', 'GATEWAY_NOT_FOUND');
}
```

### 2.7 BUG-07 — canonicalKey 去重可能误判

**文件**：[`CombinedSessionGateway.ts`](file:///E:/PY/CODES/PY_APP/app/src/session/gateway/CombinedSessionGateway.ts)

**问题**：仅按 `session.id` 去重，不同 Agent 中的同名 ID 可能被误合并。

**方案**：去重 key 改为 `agentId + session.id` 复合键。

```typescript
// 去重时使用 agentId + sessionId 复合键
const seen = new Map<string, Session>();

for (const { gateway, agentId } of activeEntries) {
  const sessions = await gateway.getSessions();
  for (const session of sessions) {
    const compositeKey = `${agentId}:${session.id}`;  // 复合键
    const existing = seen.get(compositeKey);

    if (!existing || session.updatedAt > existing.updatedAt) {
      seen.set(compositeKey, session);
    }
  }
}

return Array.from(seen.values());
```
