# 图像与视频联动设计方案

> 版本: 5.0 | 日期: 2026-07-10 | 状态: 已评审（第 3 轮）
>
> 评审记录见 §20。v5.0 变更：Phase 1→2 复用度诚实化、intendedAction 竞态修复、Worker 恢复策略、TaskCard 视觉规范、前端测试策略等 10 项。

---

## 1. 背景与现状

### 1.1 当前架构

| 页面 | 路由 | 左侧 | 右侧 |
|------|------|------|------|
| ImagePage | `/image` | ImageToolPanel（图像工具面板） | ImageGallery（图库网格，无限滚动） |
| VideoPage | `/video` | 视频生成表单（文生视频/图生视频） | 视频库网格 |
| MediaPage | `/media` | 混合视图（基础实现，未被路由启用） | — |

### 1.2 核心问题

1. **图与视频割裂**：ImagePage 和 VideoPage 完全独立，用户在图库看到好图想做视频，需下载→再上传
2. **VideoPage 图生视频使用本地上传**，无法直接引用 ImageGallery 中已生成的图片
3. **异步任务管理缺失**：视频生成是同步表单提交，无任务队列/进度/状态管理
4. **布局分散**：两个页面各占一个路由，资源浪费且体验不连贯

### 1.3 业界对标

#### Microsoft Copilot Imagine

> 来源：`logs/Microsoft Copilot_ 你的 AI 助手.html`（copilot.microsoft.com/imagine SSR 渲染内容）

| 设计要点 | Copilot 做法 |
|---------|-------------|
| 统一入口 | 只有"想像"一个页面，不分离图像/视频 |
| 画廊布局 | Masonry 瀑布流，200 张图片/视频混合无限滚动 |
| 顶部操作区 | 12 种风格预设横滑轮播（图生图入口），hover 显示"上传图像" |
| 视频处理 | 视频作为画廊第 8 张卡片，auto-play 内嵌 |
| 交互极简 | 无复杂参数面板，入口即「选风格→上传图→出结果」 |

#### Grok Imagine（xAI）

> 来源：`logs/Imagine - Grok.html`（grok.com/imagine SSR 渲染内容）

| 设计要点 | Grok 做法 |
|---------|---------|
| **底部模式切换** | 底部输入栏 segmented control：**图片 \| 视频 \| 代理**，切换后参数区域动态变化 |
| **模板预设 I2I2V** | 顶部模板卡片轮播，大部分是 I2I（图生图）或 I2I2V（图生图再生视频），用户上传图→选模板→一键生成 |
| **卡片级操作** | 画廊中每张图片卡片右上角有操作按钮（爱心/更多），可直接从图片发起视频生成 |
| **历史混合展示** | 左侧 sidebar 历史记录用 4 列网格混合展示图片和视频，视频卡片有播放图标标识 |
| **参数动态适配** | 图片模式：数量(1/2/4) + 宽高比(2:3/1:1/3:2/16:9)；视频模式：时长(5-10s) + 宽高比 |
| **I2V 自然融合** | 底层 API 已将 I2V 和 T2V 统一，上传图片后直接可在输入栏输入 prompt 生成视频 |

### 1.4 对标总结

```
Copilot Imagine                        Grok Imagine
──────────────                        ────────────
全屏 Masonry 画廊                      左侧历史 + 右侧 Masonry 探索
仅图生图风格轮播                       顶部模板（I2I + I2I2V）+ 底部输入栏
视频混入画廊 auto-play                 视频混入，卡片级操作触发视频生成
无模式切换                             底部 segmented control 图片/视频/代理
极简无参数                             模式相关参数（数量、时长、宽高比）

共同点:
✅ 统一页面，不分离图/视频
✅ Masonry 瀑布流混合展示
✅ 视频 auto-play 内嵌
✅ 模板/预设降低操作门槛
✅ 图片→视频是自然流程，不是跳页操作
```

## 2. 设计目标

1. **统一媒体页**：用 MediaPage 替代独立 ImagePage / VideoPage，图像和视频在同一视图中创作与浏览
2. **卡片级联动**：画廊中每张图片卡片即可直接触发视频生成（对标 Grok），无需先跳转页面
3. **Masonry 混合画廊**：图片和视频在同一瀑布流中展示，无限滚动，视频卡片 auto-play（对标 Copilot + Grok）
4. **底部统一输入栏**：segmented control 图片/视频 模式切换，参数随模式动态变化（对标 Grok）
5. **模板预设系统**：I2I / I2I2V 模板卡片轮播，降低操作门槛（对标 Grok + Copilot）
6. **异步任务管理**：视频生成为异步模式（创建 → 轮询 → 完成通知），支持并发多任务，含并发控制
7. **集中状态管理**：用 Zustand MediaStore 统一管理跨组件状态
8. **性能可量化**：Masonry 虚拟化、渲染时间、滚动帧率均有明确指标

## 4. 集中状态管理：MediaStore（评审新增）

> **评审意见 #2**：组件树很详细但缺少状态管理层。MediaPage 需要管理画廊数据、选中媒体、操作模式、任务队列、模板选择等跨组件状态。

### 4.1 Zustand Store 定义

```typescript
import { create } from 'zustand';

interface MediaItem {
  id: string;
  type: 'image' | 'video';
  url: string;
  thumbnailUrl: string;
  width: number;
  height: number;
  // ★ v5.0: Masonry 布局用的宽高比（第 3 轮评审 #7）
  // 视频卡片比图片多底部控件（播放图标 + 时长标签 ~32px），需要额外高度
  uiAspectRatio: number;   // image = height/width, video = (height+32)/width
  // 视频专属
  duration?: number;
  sourceImageUrl?: string;     // 视频的来源图片（追溯用）
  // 生成来源
  generatedByTemplate?: string; // 如果是模板生成，记录模板 ID
}

/**
 * 媒体页统一状态管理
 * 替代组件间 props 层层传递，所有跨组件通信走 Store
 */
interface MediaStore {
  // ──── 画廊 ────
  galleryItems: MediaItem[];
  galleryLoading: boolean;
  galleryHasMore: boolean;
  selectedId: string | null;

  // ──── 输入面板 ────
  mode: 'image' | 'video';
  prompt: string;
  selectedImageUrl: string | null;   // 图生视频时的来源图
  selectedImageId: string | null;
  params: {
    count?: number;                  // 图片模式：生成数量 1/2/4
    duration?: number;               // 视频模式：时长 5/8/10 秒
    aspectRatio: string;             // 宽高比
    style?: string;                  // 风格（可选）
  };

  // ──── 任务队列 ────
  activeTasks: VideoTask[];
  maxConcurrency: number;            // 最大并发数，默认 2

  // ──── 模板 ────
  templates: MediaTemplate[];
  activeTemplateId: string | null;

  // ──── 布局 ────
  isGalleryCollapsed: boolean;
  isTemplateCarouselExpanded: boolean;
  previewVisible: boolean;

  // ──── 跨组件操作意图（卡片→输入栏） ────
  // ★ v5.0: 加 seq 序列号解决竞态（第 3 轮评审 #3）
  intendedAction: {
    seq: number;                       // 递增序列号，消费方比对判断是否过期
    type: 'generate-video' | 'edit-image' | null;
    sourceImage: { id: string; url: string } | null;
    autoSubmit: boolean;               // true = 立即触发（对标 Grok 极简流）
  } | null;
  lastConsumedSeq: number;            // 消费方记录，用于去重

  // ──── Actions ────
  selectMedia: (id: string) => void;
  setMode: (mode: 'image' | 'video') => void;
  setPrompt: (prompt: string) => void;
  setSelectedImage: (url: string, id: string) => void;
  clearSelectedImage: () => void;
  setParams: (params: Partial<MediaStore['params']>) => void;
  addTask: (task: VideoTask) => void;            // sync: 添加到本地队列
  fetchAndAddTask: (taskId: string) => Promise<void>;  // ★ async: 调 API + set
  updateTask: (taskId: string, update: Partial<VideoTask>) => void;  // sync
  removeTask: (taskId: string) => void;
  selectTemplate: (templateId: string | null) => void;
  setIntendedAction: (action: Omit<MediaStore['intendedAction'], 'seq'>) => void;  // ★ 内部自增 seq
  clearIntendedAction: () => void;
  toggleGallery: () => void;
  setGalleryItems: (items: MediaItem[], hasMore: boolean) => void;  // sync
  fetchGalleryItems: (params: GalleryParams) => Promise<void>;      // ★ async
  appendGalleryItems: (items: MediaItem[], hasMore: boolean) => void; // sync
}
```

### 4.2 跨组件通信路径（评审 #10 落地，第 3 轮加竞态保护）

```
Card ActionMenu 点击"生成视频"
  → store.setIntendedAction({
      type: 'generate-video',
      sourceImage: { id, url },
      autoSubmit: false,
    })
  → setIntendedAction 内部: seq++, 写入 store

BottomInputBar 订阅 intendedAction
  → useEffect 检测到 action && action.seq > store.lastConsumedSeq
  → 消费: 自动切换 mode='video' + 回填 selectedImageUrl
  → store.lastConsumedSeq = action.seq  (★ 防止重复消费)
  → store.clearIntendedAction()

TemplateCarousel 点击模板卡片
  → store.selectTemplate(templateId)
  → store.setIntendedAction({ type: 'generate-video', ...autoSubmit: true })
  → BottomInputBar 检测到 → 填入模板 prompt → 自动触发生成

★ 竞态保护（第 3 轮评审 #3）:
  - 用户快速点击卡片 A→卡片 B：B 的 seq 更大，A 被自然覆盖
  - 消费方用 lastConsumedSeq 去重：seq <= lastConsumedSeq 的 action 视为已过期
  - autoSubmit=true 时消费方额外校验 sourceImage 是否与当前 selectedImageId 一致
```

> **设计原则**：`intendedAction` 始终为**最新意图**（最新 seq 覆盖旧值），而非完整队列。因为用户快速操作时，通常只需要最后一个操作生效——前面的中间操作无需依次执行。

## 5. Phase 1 设计：MediaPage MVP

### 5.1 总体思路

- **直接在 MediaPage 上迭代**，Phase 1 不做 Masonry、不做模板轮播、不做底部输入栏
- 左侧：现有 ImageGallery 网格（带搜索+筛选）
- 右侧：图生视频表单 + 异步任务进度
- 旧 ImagePage / VideoPage 保持不变
- 后端：异步视频生成任务管理

### 5.2 用户工作流

```
1. 用户进入 /media (MediaPage)
2. 左侧浏览图库（网格，支持搜索 + 日期筛选）
3. 点击选中某张图片 → 右侧回显预览
4. 填写提示词（可选）
5. 点击「生成视频」→ 创建异步任务
6. 右侧任务卡片实时更新进度
7. 生成完成 → 右侧切换为视频播放器，左侧图库追加新视频卡片
```

### 5.3 组件架构

```
MediaPage (Phase 1 MVP)
├── LeftPanel
│   ├── SearchBar                    ★ 新增（搜索 + 日期筛选）
│   └── ImageGallery                 (复用，带 selectMode + 视频类型支持) ★ 改造
│       ├── ImageCard                (已有)
│       └── VideoCardBadge           ★ 新增：视频卡片叠层（播放图标 + 时长标签）
│
├── RightPanel
│   ├── FileDropZone                 ★ 新增：本地上传拖拽区（简化版）
│   ├── SelectedImagePreview
│   ├── PromptInput
│   ├── GenerateButton
│   └── TaskList
│       └── TaskCard × N
│
└── useMediaStore                    ★ 状态管理（从 Phase 1 开始就引入）
```

> **第 3 轮评审补齐**：
> - **ImageGallery 视频卡片支持**：生成的视频需在左侧图库展示，ImageGallery 增加 `type: 'video'` 识别，视频卡片叠加播放图标 + 时长标签，点击播放（而非打开 ImageViewer）。
> - **本地上传入口**：右侧新增 `FileDropZone`（简化版 ImageUploadDrop），用户可选本地图片作为视频来源。

### 5.4 图库搜索/筛选增强（评审 #3 补齐）


> 弹窗和图库面板都带搜索，避免用户几百张图翻到崩溃。

### 5.5 TaskCard 状态/UI 映射表（第 3 轮评审 #4 补齐）

> 每个任务状态在 TaskCard 上的视觉呈现需有统一规范。

| 状态 | 图标/动画 | 文案 | 进度条 | 操作按钮 |
|------|:---:|------|:---:|------|
| `pending` | ⏳ 旋转加载动画 | "准备中…" | 灰色 0% | 取消 |
| `queued` | 🕐 时钟图标 | "排队中(第 N 位)" | 灰色 0% | 取消 |
| `running` | 🔄 旋转 + 进度 | "生成中 {progress}%" | 蓝色 progress% | 取消 |
| `completed` | ▶ 播放图标 + 时长标签 | 时长 5s \| 3.2 MB | 绿色 100% | 播放 \| 下载 \| 删除 |
| `failed` | ❌ 红色叉号 | "{error 摘要}" | 红色定格 | 重试 \| 删除 |

**取消行为**：
- `pending` / `queued` → 直接从队列移除，DB 记录标记 `cancelled`
- `running` → 尝试中断 Provider 调用（如支持），标记 `cancelled`；若 Provider 不支持中断，任务继续但前端不展示结果

## 6. Phase 2 设计：统一媒体工作台

### 6.1 整体布局（含响应式双模式）

> **评审意见 #9**：三栏布局 + 顶部模板 + 底部输入栏对 1366×768 不友好。
> **优化**：紧凑模式 / 完整模式 自适应切换。

```
紧凑模式（无选中媒体时，默认）
┌──────────────────────────────────────────┐
│  媒体工作台                                │
│  模板轮播: [Chibi] [Comic] ... ← 一行小图标 │
│  ┌──────────────────────────────────────┐ │
│  │  [图片 | 视频]  提示词...  [参数] [生成] │ │
│  └──────────────────────────────────────┘ │
│  ┌──────────────────────────────────────┐ │
│  │  Masonry 画廊（全宽）                  │ │
│  └──────────────────────────────────────┘ │
└──────────────────────────────────────────┘

完整模式（选中媒体后，自动展开）
┌──────────────────────────────────────────┐
│  媒体工作台                                │
│  模板轮播: [Chibi] [Comic] [Showcase] ...  │  ← 展开横滑
├─────────────┬────────────────────────────┤
│  Masonry     │  预览 / 操作区              │
│  画廊        │                            │
│  (可折叠)    │  选中媒体大图预览            │
│             │  ── 异步任务进度 ──         │
│             │  生成中 ████████░░ 80%      │
│             │  完成: [▶ 播放]              │
├─────────────┴────────────────────────────┤
│  [图片 | 视频]  提示词...  [数量▼] [比例▼] [生成]│
└──────────────────────────────────────────┘
```

**切换规则**：
- `store.selectedId === null` → 紧凑模式（画廊全宽，底部输入栏撑满）
- `store.selectedId !== null` → 完整模式（左右分栏，预览区显示）

### 6.2 底部输入栏设计（对标 Grok）

```
┌──────────────────────────────────────────────────────────────┐
│  ○ 图片  ● 视频                                              │  ← segmented control
│  ┌──────────────────────────────────────────────────────┐    │
│  │  描述你想生成的视频内容...                               │    │  ← 提示词输入
│  └──────────────────────────────────────────────────────┘    │
│  选中图片: [🖼️ 缩略图] ✕    [时长 5s ▼]  [宽高比 16:9 ▼]  [生成] │  ← 动态参数
└──────────────────────────────────────────────────────────────┘

切换到「图片」模式后:
┌──────────────────────────────────────────────────────────────┐
│  ● 图片  ○ 视频                                              │
│  ┌──────────────────────────────────────────────────────┐    │
│  │  描述你想生成的图片内容...                               │    │
│  └──────────────────────────────────────────────────────┘    │
│  [数量 2 ▼]  [宽高比 1:1 ▼]  [风格 无 ▼]            [生成]    │  ← 不同参数组
└──────────────────────────────────────────────────────────────┘
```

**动态参数对照**：

| 模式 | 参数项 |
|------|--------|
| 图片 | 数量（1/2/4）、宽高比（2:3/1:1/3:2/16:9）、风格（可选） |
| 视频 | 时长（5s/8s/10s）、宽高比（16:9/9:16/1:1） |
| 图生视频时 | 额外显示：选中图片缩略图 + 移除按钮 |

### 6.3 模板预设系统（评审 #8 补齐种子数据）

```typescript
  category: string;
  requiresImage: boolean;
```

**种子模板数据**：

### 6.6 Masonry 虚拟化方案（评审 #7 补齐）

> **评审意见 #7**：200+ 卡片 + 自动播放视频，不用虚拟化 DOM 节点会爆炸。

**技术选型**：`react-virtuoso` 的 `Masonry` 模式

```typescript
import { Masonry } from 'react-virtuoso';

<Masonry
  items={galleryItems}
  itemContent={(index, item) => <MediaCard item={item} />}
  // 每张卡片高度自适应（瀑布流核心）
  computeItemKey={(index, item) => item.id}
  // 仅渲染可视区域 + 上下各 2 行缓冲
  overscan={2 * columnCount}
/>
```

**双重保障**：
1. `react-virtuoso Masonry` — 虚拟化 DOM，仅渲染可视卡片
2. `content-visibility: auto` — 每张 `MediaCard` 自带 CSS containment，浏览器层面跳过不可见卡片的布局计算

**视频自动播放控制**：

```typescript
// IntersectionObserver 控制视频播放
// 仅当卡片进入可视区域时才启动 <video autoplay>
function MediaCard({ item }: { item: MediaItem }) {
  const videoRef = useRef<HTMLVideoElement>(null);

  useEffect(() => {
    const observer = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) {
        videoRef.current?.play();
      } else {
        videoRef.current?.pause();
      }
    }, { threshold: 0.5 });

    if (videoRef.current) observer.observe(videoRef.current);
    return () => observer.disconnect();
  }, []);

  if (item.type === 'video') {
    return <video ref={videoRef} src={item.url} muted loop playsinline />;
  }
  return <img src={item.thumbnailUrl} />;
}
```

## 10. 异步任务管理

### 10.1 任务状态机（含排队）

```
         ┌─────────┐
         │ pending │  ← 任务已创建
         └────┬────┘
              │
              ▼
         ┌─────────┐
    ┌───→│ queued  │  ← 等待执行（并发数已满时进入）★ 评审 #5
    │    └────┬────┘
    │         │ 有空闲 slot
    │         ▼
    │    ┌─────────┐
    └────│ running │  ← 正在生成中
         └────┬────┘
         ┌────┴────┐
    ┌────▼───┐ ┌──▼──────┐
    │completed│ │ failed  │
    └────────┘ └─────────┘
```

### 10.2 并发控制策略（评审 #5 补齐）

| 参数 | 值 | 说明 |
|------|:---:|------|
| 最大并发数 | 2 | 默认值，可通过环境变量 `VIDEO_TASK_CONCURRENCY` 调整 |
| 排队策略 | FIFO | 按 `queued_at` 先进先出 |
| 超时 | 5 分钟 | 单个任务最大执行时间 |
| 重启恢复 | 扫描 `status=running` → 标记 `failed`；扫描 `status=queued` → 恢复排队 |

```typescript
class VideoTaskManager {
  private maxConcurrency = parseInt(process.env.VIDEO_TASK_CONCURRENCY || '2');
  private runningCount = 0;
  private queue: string[] = [];

  async createTask(params: CreateTaskParams): Promise<VideoTask> {
    const task = await db.insert(video_tasks, { ...params, status: 'pending' });

    if (this.runningCount >= this.maxConcurrency) {
      await db.update(video_tasks, task.taskId, { status: 'queued', queued_at: new Date().toISOString() });
      this.queue.push(task.taskId);
    } else {
      this.startTask(task.taskId);
    }
    return task;
  }

  private async startTask(taskId: string): Promise<void> { /* runningCount++ → execute → runningCount-- → dequeue */ }
  private async dequeue(): Promise<void> { /* 从队列取下一个任务执行 */ }
}
```

### 10.4 后端执行流程

```
createTask()
  → 写入 DB (status=pending)
  → 检查并发数
    → < max → startTask (status=running, started_at=now)
    → >= max → 入队列 (status=queued, queued_at=now)
  → Worker 执行
    → 调用 Provider API 生成视频
    → 轮询 Provider 进度，同步更新 progress
    → 生成完成:
      → 保存视频到 ~/.pyapp/media/
      → 写入 videos 表
      → updateTaskStatus(status=completed)
      → dequeue() 取下一个任务
    → 生成失败:
      → 重试（最多 3 次）
      → updateTaskStatus(status=failed, error=...)
      → dequeue()

启动恢复（第 3 轮评审 #6 修正）:
  1. 扫描 status=running
     → 检查 started_at 距今是否 > 10 分钟（grace period: 10 分钟）
     → 超过: 标记 failed（任务确实丢失）
     → 未超过: 检查 Provider 端是否仍 active
       → 仍 active: 保留 running，恢复轮询
       → 已不存在: 标记 failed
  2. 扫描 status=queued → 重新入队列
  3. 扫描 status=pending → 已超过 5 分钟 → 标记 failed
```

> **grace period 说明**：后端短暂重启（秒级）不应该导致正在执行的任务丢失。10 分钟 grace period 覆盖了重启 + 依赖服务恢复的合理时间窗口。

```typescript
// Worker 恢复测试（第 3 轮评审 #6 关键场景）
test('重启时 running 任务未超时则保留 running', () => {
  // 创建一个 started_at = 2分钟前的 task
  // 模拟重启 → 扫描 running → 2min < 10min → 保留 running
  expect(task.status).toBe('running');
});
```

## 16. 边界情况

| 场景 | 处理方式 |
|------|---------|
| 画廊为空 | 显示空状态引导（"生成第一张图片"） |
| 源图被删除 | 确认框 + 级联处理，见 §11 |
| 视频生成超时 | 5 分钟超时 → 标记 failed，提示重试 |
| 并发满时新任务 | 进入队列（status=queued），前端显示"排队中" |
| 页面刷新 | `useVideoTaskPolling` 恢复活跃任务 |
| Worker 崩溃 | 启动时扫描 running→failed，queued→恢复排队 |
| 视频自动播放 | IntersectionObserver 控制，仅可视区域播放 |
| 模板无选中图片 | 模板卡片置灰 + tooltip"请先从画廊选择一张图片" |
| 图生视频模式无图片 | 底部输入栏显示空状态引导 |

## 17. 风险与回退

| 风险 | 级别 | 缓解措施 |
|------|:---:|---------|
| Masonry 虚拟化性能 | 中 | react-virtuoso + content-visibility 双重保障 |
| 视频生成 Provider 不稳定 | 中 | 重试 3 次 + 错误信息保留 |
| 前端轮询频率过高 | 低 | 2 秒间隔 + 页面切后台暂停 |
| 旧页面功能回归 | 低 | MediaPage 是全新页面，旧路由始终保留 |

> **回退策略**：MediaPage 是新页面，旧 ImagePage 和 VideoPage 不受影响。任何阶段出问题，路由切回 `/image` 和 `/video` 即可，零风险。
