#### 1.1 消息列表日期分组 + "回到底部"按钮

**目标文件**：`ChatMessageList.tsx`、`ChatArea.tsx`

**Liri review 意见**：
- 当前 `ChatArea.tsx` 已有滚动按钮样式 `absolute bottom-16 right-6 z-10`，应**复用并改造**而非重写。
- `App.tsx` 中有 `MobileBottomNav` 固定底部，按钮定位需避免与它重叠。
- `SessionHeader.tsx` 已显示轮次计数和会话标题，日期分隔线需与它协调不冲突。

**改动**：

#### 1.3 操作按钮常驻显示

**目标文件**：`ChatMessage.tsx`

- "重新生成" vs "续写"是两个不同功能，不能混淆放在同位置。
- 流式输出中点击"重新生成"需要 `isStreaming` 守卫。

**改动**：

## 三-2、Liri 2nd Review 补全（鲁棒性 & 工程质量）

> 以下为 Liri 第二轮 review 指出的缺失维度，均为方案完整性所需。

### R1. EmptyState 具体方案

**现状**：`ChatMessageList.tsx` 欢迎页已有 logo + 欢迎语 + "开始新对话"快捷操作 + 系统状态指示。

**两级空状态**：
1. **无 session**（`!hasSession`）：展示欢迎页（logo + 欢迎语 + "开始新对话"按钮）
2. **有 session 但无消息**（`session && messages.length === 0`）：展示 "暂无消息" 空对话状态

**保持一致性要求**：
- 新版的左右交替气泡样式 → EmptyState 中的**示例对话预览**（如有）也应使用同样的气泡 + 头像样式
- 欢迎页背景色、Logo 尺寸、按钮圆角应与新版消息气泡的视觉语言一致
- EmptyState 中的快捷操作按钮应使用与常驻操作栏相同的图标+文字风格
- **"有 session 无消息"状态**：页面中间展示灰底圆角容器 + "暂无消息"文字，背景色和 `border-radius` 与新版气泡一致（`rounded-2xl bg-gray-50 dark:bg-gray-800`）

### R2. 搜索 & 导出功能纳入方案

**现状**：`ChatMessageList.tsx` 已有 `Ctrl+F` 搜索栏（`sticky top-0 z-20`）和导出 MD/JSON 按钮。

**处理**：
- **z-index 冲突**：日期分隔线使用普通流布局（非 sticky），搜索栏 `z-20` 覆盖在日期分隔线之上，不冲突
- **导出入口迁移**：导出按钮从消息列表顶部移到 `SessionHeader` 右侧，与面包屑、搜索图标平级，视觉与新版操作栏风格统一
- **搜索范围扩展**：用户消息增加 Markdown 渲染后，`getMessageSearchText` 需扩展为 `message.content + blocks.map(b => b.text).join(' ')`

### R2-2. RoundNavigator 具体定位

**现状**：`ChatArea.tsx` 中的 `RoundNavigator` 是 Liri 的独特功能（竞品均无）。

**3rd review 指出的模糊点**：方案只说"保留并优化"但未答：位置在哪？与日期分隔线谁显式谁隐式？

**方案**：
- RoundNavigator 改为**浮动侧边索引**（类似 VS Code Breadcrumb），不参与消息列表 DOM 流
- 默认**折叠为一个小圆点**在消息列表左侧边缘，hover/点击展开轮次列表
- 日期分隔线是**显式的、用户持续可见的**（按天分组）；RoundNavigator 是**隐式的、按需展开的**（按轮次跳转）
- 两者互补：日期分隔线负责时间感知，RoundNavigator 负责快速导航至特定轮次

### R3. 无障碍（a11y）

新增元素需补 aria 属性：

| 元素 | aria 要求 |
|:---|------|
| 回到底部按钮 | `aria-label="回到最新消息"`, `role="button"` |
| 流式脉冲光标 | `aria-live="polite"`, `aria-label="AI 正在生成回复"` |
| 常驻操作按钮 | 每个按钮加 `aria-label`（如"复制消息"、"重新生成"） |
| 日期分隔线 | `role="separator"`, `aria-label="2026年7月10日"` |
| 展开的 Token 信息 | `aria-expanded="true/false"` |
| ⋯ 更多菜单 | `aria-haspopup="true"`, `aria-expanded` |

### R6. 会话切换时滚动位置恢复

**问题**：`useAutoScroll` 当前在会话切换时会自动滚到底部。但如果用户之前手动滚到了历史位置，切换回来时应该恢复。

**方案**：
- 在 `sessionStore` 中为每个 sessionId 存储 `scrollPosition: number`
- `useAutoScroll` 在 sessionId 变化时：
  - 若有保存的 scrollPosition → `scrollTo(position)`
  - 否则（新会话）→ `scrollToBottom()`
- 用户手动滚动时更新 `scrollPosition`

### R7. 错误状态覆盖

#### 7a. 日期分隔线边界条件

| 场景 | 方案 |
|:---|------|
| **时区问题**：UTC vs 本地时间 | 使用 `new Date(message.timestamp).toLocaleDateString()` 基于用户本地时区（`message.timestamp` 是 Unix 毫秒） |
| **第一条消息** | 不显示日期分隔线（`i === 0 || i < 0` → skip），SessionHeader 已说明会话开始时间 |
| **空消息列表** | `messages.length === 0` 保护，不执行日期分组逻辑 |
| **formatDateLabel 异常** | try/catch → 返回空字符串 → `shouldShowDateSeparator` 判断为 false → 跳过分隔线 |
| **可测试性** | `shouldShowDateSeparator` 和 `formatDateLabel` 提取到新文件 `src/utils/dateUtils.ts`，作为独立纯函数，可直接 import 单测 |

#### 7b. 头像 fallback 完整链路

| 场景 | 方案 |
|:---|------|
| **AI 头像加载失败** | 同样显示首字母 fallback（显示 **L**），与用户头像风格一致 |
| **onError 后重复加载** | `onError` 设置 `imgFailed` state → 永久使用 fallback，不再尝试 http 加载 |
| **离线模式** | `/liri_logo.png` 不可访问 → 使用 `data:` URI 内联极简 SVG 兜底图标 |
| **用户头像加载失败** | 维持首字母+色块方案（当前已有，不依赖网络） |

#### 7c. 其他

| 场景 | 当前行为 | 方案要求 |
|:---|------|------|
| 头像图片加载失败 | 裂图 | `onError` → 显示 AI/user 的首字母 fallback |
| `formatDateLabel()` 异常 | 无防护 | try/catch → 显示 `" "`（空字符串，跳过分隔线） |
| Markdown 渲染错误 | `BlockRenderer` 内部有 ErrorBoundary | 不变，但确保错误边界内的 fallback UI 与新布局协调 |
| 空消息列表 | EmptyState | 保持不变 |
| copy API 失败 | 无反馈 | `catch` → toast "复制失败" |

### R9. useAutoScroll 状态统一

**问题**：`ChatArea.tsx` 当前有独立的 `handleScroll` + `showScrollToBottom` 状态，与 `useAutoScroll` hook 形成**两个并行滚动检测逻辑**。方案将新增 `isUserScrolledUp`，进一步加剧分裂。

**方案**：
- 将 `showScrollToBottom`（现有）+ `isUserScrolledUp`（新增）逻辑统一收进 `useAutoScroll.ts`
- `useAutoScroll` 返回值改为：
  ```ts
  { containerRef, isUserScrolledUp, scrollToBottom, distanceFromBottom }
  ```
- `ChatArea.tsx` 中移除独立的 `handleScroll` 和 `showScrollToBottom` 状态，统一从 hook 取值
- 回到底部按钮渲染条件：`isUserScrolledUp && distanceFromBottom > 200`

### R10. ChatMessage memo 比较器兼容性

**结论**：无需额外改动。当前 memo 比较器已检查 `isStreaming`、`message.content`、`message.blocks`、`message.role`、`sessionUsage`。1.3 中 `isStreaming` 通过 `disabled` 属性体现，memo 比较器已有的 `isStreaming` 检查已覆盖此场景。`showTokenInfo` 若设计为组件内部 `useState` 则也无需加入 memo。

**验证**：实现后确认 `isStreaming` 变为 `false` 时按钮从 disabled 恢复为可点击即可。

### R11. RoundNavigator 与日期分隔线的跨午夜冲突

**场景**：用户 23:50 发消息，AI 00:10 回复。RoundNavigator 将两者归为**同一轮次**，日期分隔线将其归为**不同天**。两者同时出现在消息列表时产生视觉冲突。

**方案**：
- 日期分隔线在跨午夜轮次中仍显示（用户需要感知时间跨越）
- RoundNavigator 的轮次摘要中标注"跨天"小标记（如 `🌙`）
- 优先级：日期分隔线 > RoundNavigator 分组（日期线不因 RoundNavigator 而隐藏）

### R12. Markdown 复制保留格式

**问题**：当前 `handleCopy` 调用 `getFullContent()` 提取纯文本，丢失 Markdown 格式。1.2 引入用户消息 Markdown 渲染后，复制应能保留格式。

**方案**：
- 为 `handleCopy` 增加可选参数 `asMarkdown: boolean`
- AI 消息操作栏中的"复制"默认复制 **Markdown 源码**（供粘贴到支持 MD 的场景）
- 增加 Shift+Click 复制纯文本的快捷方式
- toast 文案区分："已复制 Markdown" vs "已复制纯文本"

### R13. "编辑重发自动分支"的 UX 决策

**场景 A**：用户修改了消息的**语义**（换了 prompt）→ 应该自动创建分支。
**场景 B**：用户仅修改了**错别字**→ 不应创建分支，直接覆盖原消息更合理。

**方案**：
- 默认行为：编辑重发**不**自动分支，保持简单
- 在 `ChatInput.tsx` 编辑模式的输入框**上方**显示一个勾选框 `☐ 另存为分支`，默认不勾选
- 用户勾选后才在新分支中发送
- **内容未改守卫**：如果编辑内容与原文完全相同 → 不触发发送（toast "内容未变更"）
- **状态重置**：`editTarget.id` 变化时自动重置 `branchOnEdit = false`

**实现**：
```tsx
// ChatInput.tsx 中
const [branchOnEdit, setBranchOnEdit] = useState(false);

// 每次进入编辑模式时重置
useEffect(() => {
  if (editTarget?.id) setBranchOnEdit(false);
}, [editTarget?.id]);

// 编辑输入框上方
{editTarget && (
  <label className="flex items-center gap-2 text-xs text-gray-500 mb-1">
    <input type="checkbox" checked={branchOnEdit}
      onChange={(e) => setBranchOnEdit(e.target.checked)} />
    另存为分支
  </label>
)}

const handleSendEdit = () => {
  if (!editTarget) return;
  if (input.trim() === editTarget.content.trim()) {
    toast("内容未变更"); return;  // guard
  }
  if (branchOnEdit) {
    openBranchAndSend(editTarget, input);
  } else {
    updateOriginalMessage(editTarget.id, input);
  }
};
```

### R14. `animate-message-enter` 动画保留

**现状**：`ChatMessageList` 中每条消息有 `animate-message-enter` CSS 类。

**方案**：
- 左右交替布局后，动画保留但调整为从各自方向滑入：用户消息从右侧滑入，AI 消息从左侧滑入
- pulse dots 动画优化：使用负延迟 `animation-delay: -0.4s, -0.2s, 0s` 使 3 个圆点级联更平滑

### R15. Skeleton 骨架屏同步

**问题**：`ChatMessageList.tsx` 在 `isStreaming || switching` 时渲染 `<SkeletonMessageList count={2} />`。消息结构改为左右交替布局 + 头像后，骨架屏占位还是旧结构，加载完成会视觉跳跃。

**方案**：
- 更新 `SkeletonMessageList` 组件使占位布局匹配新版：左侧一个圆形（头像占位）+ 右侧一个矩形长条（气泡占位），宽度与新版 `max-w-[80%]` 一致
- 等待中的 AI 消息骨架靠左排列，模拟的用户消息骨架靠右排列
