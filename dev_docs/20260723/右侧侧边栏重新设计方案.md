# 右侧侧边栏重新设计方案（v5）

> 日期：2026-07-23
> 状态：设计方案（已采纳 3 轮优化建议，待评审）
> 变更：v4 → v5：修复 Tab 嵌套冲突、Phase 依赖死锁、补充空状态/角标/跳转规则、数据流反模式修正、迁移安全网强化

## 1. 现状分析

### 1.1 当前架构问题

```
App.tsx（全局布局）
├── Sidebar（左侧导航，全局）✅ 合理
├── routeElement（页面内容区，路由驱动）
│     └── ChatPageLayout ← 聊天页在这里
└── RightPanelRouter（右侧面板，全局）❌
      ├── /chat, /  → FilePreviewPanel（聊天专用）
      ├── 其他页面  → ToolPanel（万能兜底）
      └── /office, /settings → null（全宽）
```

**核心问题**：`RightPanelRouter` 是一个全局组件，用 `useLocation()` 判断当前路由来"假装"不是全局的。它不在 `ChatPageLayout` 内部，却包含了聊天专有的 `FilePreviewPanel`（以及未来的 `ChatInspector`）。

### 1.2 全量页面右侧面板现状普查

#### 判定逻辑

```
RightPanelRouter 的判定逻辑：
  当前路径 ∈ fullWidthPaths?          → 不显示（全宽 ✅）
  当前路径 ∈ panelMap (/ 或 /chat)?    → FilePreviewPanel（聊天文件面板）
  以上都不是                            → ToolPanel（万能兜底面板）
```

#### 各页面右侧面板一览

**第一类：已全宽（无右侧面板）✅**（19 页）

| 类别 | 页面数 | 占比 |
|------|--------|------|
| 已全宽 | 19 | 46% |

**结论**：在 20 个会激活 ToolPanel 的页面中，只有 **2 个（10%）** 提供了页面中没有的实用信息，其余 18 个全是导航链接/占位符/重复内容。

### 1.3 当前 FilePreviewPanel 内部结构

> **v5 新增**：FilePreviewPanel 自身有 3 个子 Tab，直接包装会产生"Tab 套 Tab"。

```
FilePreviewPanel（当前）
├── session Tab：会话文件列表 + 文件预览
├── manage Tab：全局文件统计（总文件数、总大小、最近文件）
└── usage Tab：Token 用量统计
```

**迁移去向明确**：

| FilePreviewPanel 子 Tab | 迁移去向 |
|------------------------|---------|
| session（文件列表+预览） | → ChatInspector 文件 Tab |
| usage（Token 用量） | → ChatInspector 上下文 Tab 统计分区 |
| manage（全局文件统计） | → **移除**（低价值，全局文件管理已有 `/files` 页面） |

### 1.4 存在的问题

1. **功能单一**：对话页面右侧只有"文件预览"，大量空间未利用
2. **信息割裂**：模型配置、提示词、上下文、会话信息等散落在各处
3. **工具调用不可见**：AI 正在调用什么工具、进展如何，没有专门区域展示
4. **会话上下文不透明**：用户不知道当前上下文窗口还剩多少、已用多少 Token
5. **快速操作缺失**：切换模型、调整温度等常用操作需要跳转到设置页
6. **架构不纯净**：聊天专属面板放在全局布局层，概念上不对等
7. **首页定位错位**：首页显示聊天文件面板，与首页定位不符
8. **ToolPanel 价值低**：90% 的页面的 ToolPanel 只是凑数的导航链接

---

## 2. 设计目标

1. **信息聚合**：将会话相关的所有信息集中到右侧侧边栏，减少页面跳转
2. **上下文感知**：实时展示 Token 用量、上下文窗口占用情况
3. **工具可视化**：AI 调用工具的过程可视化，用户知道 AI 在做什么
4. **快速操作**：常用设置（模型、温度、系统提示词）可直接调整
5. **渐进式展开**：默认收起不干扰阅读，需要时展开查看详情
6. **架构纯净**：聊天面板只在聊天页渲染，非聊天页全宽显示
7. **清理技术债**：移除低价值的 ToolPanel，简化全局布局

## 3. 整体设计

### 3.1 新架构：ChatInspector 嵌入 ChatPageLayout

**核心调整**：ChatInspector 不再通过全局的 `RightPanelRouter` 渲染，而是直接嵌入 `ChatPageLayout` 内部。

```
App.tsx（全局布局）
├── Sidebar（左侧导航，全局）
└── routeElement（页面内容区，路由驱动）
      ├── ChatPageLayout（聊天页）
      │     ├── SessionHistorySidebar
      │     ├── main（ChatArea）
      │     └── ChatInspector ← 聊天专用，仅聊天页渲染
      ├── OfficePage（全宽，无右侧面板）
      ├── MediaPage（全宽，无右侧面板）
      ├── CronPage（全宽，任务状态移入页面内）
      ├── TasksPage（全宽，任务状态移入页面内）
      └── ...（其余页面全宽）
```

### 3.2 新右侧侧边栏 = ChatInspector（对话督察员）

**定位**：对话页面的"控制台/信息面板"，集中展示当前会话的所有相关信息，提供快捷操作。

### 3.3 Tab 结构（4 个 Tab）

```
┌─────────────────────────────────┐
│  🔍上下文  🛠️工具  📁文件  ⚙️设置  │
├─────────────────────────────────┤
│                                 │
│  当前 Tab 的内容区               │
│                                 │
└─────────────────────────────────┘
```

| Tab | 图标 | 功能 | 优先级 |
|-----|------|------|--------|
| 上下文 | 🔍 | 上分区：上下文窗口可视化 + 系统提示词（只读）；下分区：Token/成本/会话统计 + 消息摘要 | P0 |
| 工具 | 🛠️ | 工具调用列表（进行中/完成/失败）、调用详情、重试 | P0 |
| 文件 | 📁 | 会话文件列表、文件预览（抽取纯内容组件，非包装器） | P1 |
| 设置 | ⚙️ | 模型切换、温度、top_p、系统提示词编辑（唯一编辑入口）、快捷提示词 | P1 |

> **v5 变更**：明确系统提示词的职责划分——上下文 Tab **只读展示+复制**，设置 Tab **唯一编辑入口**。
> **v5 变更**：文件 Tab 不再包装 FilePreviewPanel，而是抽取纯内容组件 `FileListViewer`。

### 3.4 交互设计

#### 收起状态（默认）

- 宽度：48px（与左侧导航栏对称）
- 显示 4 个 Tab 的图标（垂直排列）
- **点击图标 → 展开面板并跳转到对应 Tab**（非导航跳转）
- Hover 显示 Tooltip，注明 **"展开到 XX Tab"**

> **v5 新增**：收起状态支持**数字角标**，提示用户有新变化：

```
┌────┐
│ 🔍 │ ← 展开 to 上下文 Tab
│ 🛠️²│ ← 展开 to 工具 Tab（2个进行中）
│ 📁⁺¹│ ← 展开 to 文件 Tab（新生成1个文件）
│ ⚙️ │ ← 展开 to 设置 Tab
└────┘
```

| 角标类型 | 触发条件 | 样式 |
|---------|---------|------|
| 工具进行中数量 | 有进行中的工具调用 | 蓝色数字角标 |
| 新文件标记 | 会话中新生成文件 | 绿色 `+N` |
| Token 警告 | Token 超过上下文窗口 80% | 红色 `!` |

#### 展开状态

- 默认宽度：360px（可拖拽调整，范围 280px ~ `min(50vw, 480px)`）
- 顶部 Tab 栏 + 内容区
- **拖拽手柄仅在展开状态出现**，位于左侧边缘 ~6px 窄条区域
- 左上角收起按钮

> **v5 变更**：最大宽度从 `50% 视口宽度` 改为 `min(50vw, 480px)`，保证聊天区域在任何屏幕下至少有 ~600px 可用宽度。

#### 自动跳转 Tab 规则

> **v5 新增**：明确工具调用开始时的 Tab 行为。

| 场景 | 行为 |
|------|------|
| 用户在上下文 Tab，工具调用开始 | **不自动跳转**，工具 Tab 图标角标闪烁（脉冲动画） |
| 用户主动点击工具 Tab | 清空角标，停止闪烁 |
| 面板收起，工具调用开始 | 收起态图标显示数字角标 |

**核心原则**：不强迫用户切换，但通过角标和视觉提醒让用户知道有变化。

## 4. 各 Tab 详细设计

### 4.1 上下文 Tab（Context Tab）🔍

**核心功能**：让用户直观了解当前对话的上下文状态和统计数据。

```
┌─────────────────────────────────┐
│ 上下文     [刷新]                │
├─────────────────────────────────┤
│ ▸ 上下文窗口                     │  ← 上分区
│  ━━━━━━━━━━━━━━━━╺━━━━━━━━━━━   │
│  6,234 / 128,000 tokens (4.9%)  │
│                                 │
│  输入: 5,120  输出: 1,114        │
│  缓存读取: 3,400 (53%)           │
├─────────────────────────────────┤
│ ▸ 系统提示词（只读）              │  ← 只读展示 + [复制]
│ ┌─────────────────────────────┐ │
│ │ 你是一个有帮助的AI助手...     │ │
│ │ [复制]  [前往设置编辑]       │ │
│ └─────────────────────────────┘ │
├─────────────────────────────────┤
│ ▸ 消息摘要          [点击跳转]   │  ← 点击滚动到对应轮次
│  • 第1轮 - 用户提问              │
│  • 第2轮 - AI回复代码方案        │
│  • 第3轮 - 用户追问优化          │
│  • 第4轮 - 进行中...             │
├─────────────────────────────────┤
│ ▸ 会话统计                       │  ← 下分区
│  成本估算  $0.0568               │
│  • 创建时间: 10:30              │
│  • 消息轮次: 12 轮              │
│  • 工具调用: 8 次               │
│  • 生成文件: 3 个               │
└─────────────────────────────────┘
```

> **v5 变更**：系统提示词区域标注"只读"，提供 [复制] 和 [前往设置编辑] 两个操作，不再有 [编辑] 按钮。编辑统一归设置 Tab。

**上下文窗口进度条动态适配**：

> **v5 新增**：不同模型的上下文窗口大小不同，进度条需动态适配。

| 模型 | maxContextTokens | 进度条基准 |
|------|-----------------|-----------|
| gpt-4o | 128,000 | 128K |
| claude-3.5 | 200,000 | 200K |
| 其他模型 | 从 `modelRegistry` 读取 | 动态 |

**数据来源**：
- Token 用量：从 `chatStore.messages[].usage` 聚合
- 上下文窗口：从当前模型的 `maxContextTokens` 配置读取
- 系统提示词：从 `chatStore.systemPrompt` 或会话配置读取（只读）
- 消息摘要：从消息列表生成轮次摘要
- 会话信息：`sessionStore.currentSession`

**空状态设计**：

> **v5 新增**

| 场景 | 展示内容 |
|------|---------|
| 新会话，无消息 | "开始第一次对话"提示 + 空进度条（0/128K） |
| 模型未配置 | "请先在设置 Tab 中选择模型" |

### 4.3 文件 Tab（Files Tab）📁

> **v5 重大变更**：不再包装 FilePreviewPanel，改为抽取纯内容组件 `FileListViewer`，避免"Tab 套 Tab"。

**问题说明**：

FilePreviewPanel 自身有 3 个子 Tab（session/manage/usage），如果直接包装会产生嵌套 Tab：

```
ChatInspector Tab 栏：  🔍 上下文  🛠️ 工具  📁 文件  ⚙️ 设置
                                              ↓
                                    FilePreviewPanel（包装器）
                                      session | manage | usage  ← 嵌套 Tab！
```

**解决方案**：

- 抽取 FilePreviewPanel 的 session Tab 内容为独立组件 `FileListViewer`
- 文件 Tab 直接使用 `FileListViewer`，不引入 FilePreviewPanel 的 Tab 栏
- Token 统计已由上下文 Tab 覆盖，不重复
- 全局文件统计（manage Tab）**移除**（低价值，`/files` 页面已有全局文件管理）

```
client/src/components/ChatInspector/
├── FileListViewer.tsx        # 从 FilePreviewPanel 抽取的纯内容组件
│   ├── 会话文件列表
│   ├── 文件预览
│   └── 文件操作（下载、复制、打开位置）
└── FilesTab.tsx              # 文件 Tab，内部引用 FileListViewer
```

**迁移路径**：
- Phase 2：从 FilePreviewPanel 抽取 `FileListViewer` 组件，FilesTab 引用它
- Phase 3：FilePreviewPanel 标记废弃（session Tab 逻辑已迁移），最终删除

**空状态设计**：

> **v5 新增**

| 场景 | 展示内容 |
|------|---------|
| 会话中尚未生成文件 | "暂无文件" + "AI 会在需要时生成文件" |

### 4.4 设置 Tab（Settings Tab）⚙️

**核心功能**：当前会话的快速设置，无需跳转页面。**系统提示词的唯一编辑入口**。

> **v5 变更**：设置 Tab 是系统提示词的唯一编辑入口，上下文 Tab 的 [前往设置编辑] 按钮跳转到此。

**参数生效时机**：

| 参数 | 生效时机 | 说明 |
|------|---------|------|
| 模型切换 | **下次对话生效** | 当前对话已有上下文模型，切换后 tokenizer 不一致会乱码；UI 提示 "将在新对话中生效" |
| 温度 / top_p / max_tokens | **实时生效** | 不影响已发送的历史消息，仅影响后续 AI 回复 |
| 系统提示词 | **提供选项** | 「应用到当前对话（清除历史）」或「仅新对话生效」 |

│  └───────────────────────────┘  │
│                                 │

│  │                           │  │

│                                 │
├─────────────────────────────────┤

- 模型列表：`modelService.list()`
- 当前设置：`modelSwitchStore` / `chatStore`

### 5.2 状态管理

> **v5 重大变更**：UI 交互状态独立为 `chatInspectorStore`，不再混入 chatStore。

**新增 Store**：`chatInspectorStore`（zustand slice）

| 状态 | Store | 说明 |
|------|-------|------|
| `isOpen` | chatInspectorStore | 面板是否展开 |
| `activeTab` | chatInspectorStore | 当前激活的 Tab |
| `panelWidth` | chatInspectorStore | 面板宽度 |
| `highlightedRoundId` | chatInspectorStore | 消息摘要点击跳转的目标轮次 ID（原 scrollToRoundId） |
| Token 用量 | `chatStore.messages` | 从消息聚合（只读） |
| 工具调用 | `chatStore.messages` | 从消息提取（只读） |
| 模型配置 | `modelSwitchStore` | 当前模型和参数（只读） |

**为什么 UI 状态不放在 chatStore**：

> `chatStore` 管理的是对话数据（消息列表、会话状态），`highlightedRoundId` / `isOpen` / `activeTab` 是纯 UI 交互状态。混入会违反单一职责原则，且 chatStore 的每次变更会触发所有订阅组件重渲染。

```typescript

interface ChatInspectorState {
  isOpen: boolean;
  activeTab: 'context' | 'tools' | 'files' | 'settings';
  panelWidth: number;
  highlightedRoundId: string | null;

  setOpen: (open: boolean) => void;
  setActiveTab: (tab: ChatInspectorState['activeTab']) => void;
  setPanelWidth: (width: number) => void;
  setHighlightedRoundId: (id: string | null) => void;
}

export const useChatInspectorStore = create<ChatInspectorState>(...);
```

### 5.3 性能优化策略

#### Token 统计（低频变化）

> **v5 变更**：更精确的缓存依赖链，区分流式输出和完成状态。

```typescript
// 精确的缓存依赖链
const tokenStats = useMemo(() => {
  return aggregateTokenUsage(messages);
}, [
  messages.length,                    // 消息数量变化时重算
  messages[messages.length - 1]?.usage, // 最后一轮 usage 变化时重算
]);

// 流式输出期间（content 频繁变化但 usage 未出现）→ 返回缓存值，不重算
// usage 出现后（消息完成）→ 触发一次精确计算
```

| 场景 | 缓存行为 |
|------|---------|
| 普通消息（用户/AI文本）追加 | `messages.length` 变化 → 重算 ✅ |
| 工具调用结果追加 | `messages.length` 变化 → 重算 ✅ |
| 流式输出（未完成，content 变化但 usage 未出现） | **不重算**，返回缓存值 |
| 流式完成（usage 出现） | 触发一次精确计算 |

#### 工具调用进度（高频变化）

- **SSE 增量更新 + requestAnimationFrame 渲染**：避免频繁 setState 导致整个 ChatInspector 重渲染
- 使用 `useRef` 存储最新进度，rAF 中批量更新 DOM

### 5.5 收起/展开状态持久化

- 使用 `localStorage` 保存展开状态和宽度
- 键名格式：`chatInspector:v1:isOpen`、`chatInspector:v1:width`、`chatInspector:v1:activeTab`
- 读取时校验版本号，版本不匹配时自动重置为默认值

```typescript
const STORAGE_VERSION = "v1";

function loadSetting<T>(key: string, defaultValue: T): T {
  const fullKey = `chatInspector:${STORAGE_VERSION}:${key}`;
  const raw = localStorage.getItem(fullKey);
  if (raw === null) return defaultValue;
  try {
    return JSON.parse(raw) as T;
  } catch {
    return defaultValue;
  }
}
```

## 8. 风险与注意事项

1. **性能**：右侧面板实时更新 Token 统计和工具进度

   - 已解决：系统提示词上下文 Tab 只读，设置 Tab 唯一编辑入口（见 §4.1/§4.4）
