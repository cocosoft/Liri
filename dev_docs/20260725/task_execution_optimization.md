# AI 助手任务执行行为优化方案

> 基于 2026-07-25 知识库对标任务复盘 | 聚焦任务执行流程而非技术实现

---

## 一、问题复盘

### 1.1 典型故障模式

在知识库对标分析任务中，暴露了以下执行行为问题：

| # | 故障 | 具体表现 | 根因 |
|---|------|---------|------|
| 1 | **输出 ≠ 执行** | 用户要求"完善可观测性建议"后，助手输出了长篇分析报告，但未实际调用 `file_edit`/`file_write`。用户追问"完成情况如何"才发现遗漏 | 将"思考完成"误判为"任务完成"，缺少执行后验证 |
| 2 | **缺少主动报告** | 多次出现任务实际已完成但助手未主动汇报，需用户追问才告知 | 缺少任务完成后的强制总结模板 |
| 3 | **Todo 不同步** | 标记了多个 completed 但后续又在继续操作，或标记了 in_progress 但未做任何事 | Todo 更新与实际进度脱节 |
| 4 | **子任务遗漏** | 多步骤任务中，部分子步骤被跳过（如本次对了 10 条意见但实际只改了文件、未确认全部生效） | 缺少子任务完成后的逐项自检 |

### 1.2 根因分析

```
接收到复杂任务
  │
  ├─ 输出分析文字（Token 消耗大，自身产生"完成感"）
  │
  ├─ 跳过执行落地（file_write/edit 未被调用）
  │
  ├─ 跳过主动汇报（没有输出完成总结）
  │
  └─ 等待用户追问 → 才发现遗漏 → 补救
```

**核心矛盾**：大语言模型的"文本输出"和"工具调用"是完全独立的两种行为。输出详细分析时，模型容易进入"已回答完毕"的状态，忽略了"工具尚未调用"的事实。

## 二、优化措施

### 2.1 任务完成自检清单（强制）

每次回复前，自动套用以下清单自检。任一 ☐ → 先补完再输出。

```
┌─ 任务完成自检清单 ────────────────────────┐
│                                            │
│  ☐ TodoWrite 状态与实际进度一致？           │
│     └─ in_progress 的任务是否确实在执行中？  │
│     └─ completed 的任务是否全部落地完成？    │
│                                            │
│  ☐ 若任务需写文件，file_write/edit 已执行？  │
│     └─ 是否已至少 Read 过目标文件？          │
│                                            │
│  ☐ 若任务需运行命令，RunCommand 已执行？     │
│     └─ 是否检查过退出码和输出？             │
│                                            │
│  ☐ 所有子步骤是否都已处理？                 │
│     └─ 对照用户原始指令逐条核查              │
│                                            │
│  ☐ 是否有待确认事项需向用户报告？            │
│     └─ 如是，是否已明确标注？                │
│                                            │
│  ☐ 若以上全部 ☑ → 输出任务完成总结          │
│                                            │
└────────────────────────────────────────────┘
```

### 2.2 区分"分析"与"执行"（状态标记）

**原则**：文字分析输出 ≠ 任务完成。只有工具调用全部落地的回复才视为"任务完成"。

每条回复开头自动判定状态并标注：

```
┌─ 当前回复状态 ─────────────────┐
│                                │
│  [分析中]  仅输出分析文字       │
│   → 结尾标注"⚠ 以上为分析建议" │
│                                │
│  [执行中]  部分工具已调用       │
│   → 结尾标注当前进度            │
│                                │
│  [已完成]  所有工具调用落地     │
│   → 结尾输出完成总结            │
│                                │
└────────────────────────────────┘
```

### 2.3 任务完成总结模板（强制）

每次任务全部完成后，必须输出以下格式的结构化总结：

```
✅ 任务完成

| 属性 | 内容 |
|------|------|
| 变更文件 | X 个（[file1](path1) / [file2](path2)） |
| 仅读未改 | X 个（[file3](path3) - 原因） |
| 新建文件 | X 个（[file4](path4)） |
| 待确认 | Z 项（xxx 需用户决定） |
| 提醒 | 任何需要注意的事项 |

核心变更：
- 文件 A: 写入/修改了 XXX（原因：YYY）
- 文件 B: 新增了 ZZZ
```

### 2.4 并行任务分批验证

当启动多个并行的 Task/工具调用时：

```
并行执行 N 个工具调用
  │
  ├─ 等待全部返回
  │
  ├─ 逐条检查返回结果（错误码、输出内容）
  │
  ├─ 任一失败 → 分析原因 → 修复 → 重试
  │
  └─ 全部成功 → 继续下一步
```

## 四、验证方式

### 4.1 自测场景

以下场景中，助手必须触发自检清单：

| 场景 | 应触发行为 |
|------|----------|
| 用户要求"写一个文件" | 写完后输出完成总结 |
| 用户要求"修改多处" | 每处修改后更新 Todo，全部完成后输出总结 |
| 用户要求"分析并给出方案" | 如果只有分析文字没有代码落地，结尾标注"⚠ 以上为分析建议" |
| 多个并行工具调用 | 全部返回后逐条检查结果 |

### 4.2 回归标准

连续 3 次复杂任务中，全部满足以下条件视为优化生效：
- [ ] 无"用户追问才发现遗漏"的事件
- [ ] 每次任务完成都有结构化总结
- [ ] Todo 状态与实际进度一致
