# 项目管理的自然化设计方案

> 核心命题：怎么管项目，更像人类用计算机，而不是像项目经理用 Jira？

---

## 一、问题诊断

现代项目管理工具（Jira、Notion、Linear）的共同问题是**发明了一种人类本来不需要的交互模式**：

| 人类自然行为 | 软件强加的模式 |
|------------|-------------|
| 桌面上放文件夹 | 新建项目 → 填表单 → 选模板 |
| 跟人聊天说事 | 创建 Issue → 选类型 → 填字段 |
| 记个便签 | 状态机：待办 → 进行中 → 已完成 |
| 翻聊天记录找上次说的 | 学会用看板/甘特图/筛选器 |

**根因**：这些工具把人当成了"项目经理"，但实际上绝大多数人是"做事的人"。做事的人只需要三样东西：**说话、记住、找到**。

---

## 二、核心设计哲学

### 一句话模型

```
项目 = 文件夹（存东西）+ 聊天记录（过程）
```

用户不需要"管理"项目，只需要：
- **说话** → 事就办了
- **记住** → AI 自动记录
- **找到** → 搜索/最近

### 三条铁律

1. **项目是长出来的，不是建出来的**
   - 用户不需要主动"新建项目"，AI 在对话中发现复杂话题时自动创建
   - 创建过程零交互：用户可能都没注意到项目已经存在了

2. **项目不需要管理，只需要找到**
   - 人类不管理文件夹结构，人类搜索
   - 最近用的自然在上面，不用的自然沉底
   - 没有"归档"按钮——不活跃 = 自动休眠

3. **项目是会话的标签，不是会话的牢笼**
   - 一个会话可以关联到项目，但不是必须
   - 资料/成果可以跨项目引用
   - 切换项目不需要"离开"任何东西

## 三、用户体感对比

### 现在（软件味）

```
用户：打开侧栏 → 找到项目 → 点击 → 看到项目列表
  → 点"新建项目" → 起名字 → 确认
  → 在空白的项目页里开始聊天
  → 聊完了，项目留在列表里，永远不删
  → 一个月后有 20 个项目，分不清哪个是哪个
```

### 方案（自然感）

```
用户：打开应用 → 开始聊天
  → 聊着聊着，AI 说"这个话题我帮你整理了一下"
  → 侧栏多了一个项目（用户没主动创建）
  → 右侧面板自动出现：资料 / 成果 / 讨论记录
  → 以后再聊这个话题，AI 自动关联到这个项目
  → 一个月没碰的项目自动沉到底部
  → 想找就说一句话："上次聊那个记账的怎么样了？"
```

## 四、三个核心改动（按优先级）

### 改动 1：AI 自动建项目（P0）

**现状**：AI 在 system prompt 中被引导"建议建项目"，用户需要手动操作。

**改为**：AI 直接创建项目，不需要用户确认。

**触发条件**（满足任一）：
- 一轮对话中产生了 3 个以上不同的产出物（计划、代码、文档等）
- 用户表达了明确的长期目标（"我要做一个..."、"帮我规划..."）
- 同一话题连续聊了 5 轮以上
- ImplicitEngineHook 检测到 goal + 至少 2 个 deliverables

**实现**：
```
ChatManager._finalizeStreamMessage()
  → ImplicitEngineHook.persist() 返回 { hasGoal, deliverables }
  → if hasGoal && deliverables.length >= 2 && !已有项目关联:
      → 自动调用 ProjectStore.create({ name: 从 goal 提取, ... })
      → 将当前 session.worktreeId 设为新项目 ID
      → 迁移已有的 context/artifacts 到新项目
      → 静默完成，不打断用户
```

**用户体验**：聊着聊着，右侧面板突然有内容了——项目已经存在了。不需要"创建"这个动作。

### 改动 2：搜索 + 活跃度排序（P1）

**现状**：项目列表按创建顺序排列，无搜索。

**改为**：

**2a. 搜索框**
- 列表顶部增加搜索输入框
- 实时过滤：匹配项目名称 + 项目内会话标题
- 搜索结果高亮匹配文字

**2b. 活跃度排序**
- 默认按"最近一次会话时间"排序
- 今天聊过的置顶
- 标记活跃度：🟢 今天 | 🟡 本周 | ⚪ 更早

**2c. 智能建议**
- 无搜索结果时，提示："没有找到「XXX」，要不要用 AI 搜索所有聊天记录？"

### 改动 3：项目休眠机制（P2）

**现状**：所有项目平铺在列表中，永不消失。

**改为**：

```
列表分区：
  ┌─ 活跃（最近 7 天有会话）── 全部展开
  ├─ 休眠（7-30 天无会话）  ── 默认折叠，显示 "(3 个项目)"
  └─ 归档（30 天以上）       ── 默认隐藏，底部"查看归档"入口
```

- 休眠和归档只是**视觉隐藏**，不删除数据
- 重新在这个项目里聊天 → 自动回到活跃区
- 归档区的项目在搜索结果中仍然可见

## 五、与现有系统的衔接

### 和 PDCA 隐性引擎的关系

```
自然化项目管理 = 外层体验
PDCA 隐性引擎 = 内层驱动力

体验层：用户只管聊天，项目自己长出来
驱动层：AI 在每次对话中隐性执行 Plan→Do→Check→Act
```

自动化建项目后，升级通道变为：
```
聊天 → 检测到复杂目标 → 自动建项目 + 启动 PDCA 循环
（以前：聊天 → AI 建议 → 用户手动建 → 手动启动 PDCA）
```

### 数据模型不变

- Project 类型已有 `pdcaIds`、`phase`、`workItemIds`
- 引擎钩子已有 `hasGoal` 返回值
- 无需新增字段，改动全在交互层

### 改动范围

| 优先级 | 改动 | 涉及文件 | 工作量 |
|:--:|------|---------|:--:|
| P0 | AI 自动建项目 | `ChatManager.ts`、`ImplicitEngineHook.ts`、`systemPromptSections.ts` | ~2h |
| P1 | 搜索 + 排序 | `ProjectsPage.tsx`（左栏） | ~1h |
| P2 | 休眠分区 | `ProjectsPage.tsx`（左栏） | ~1h |

## 六、验收标准

### 用户视角

1. **零操作建项目**：一次对话聊到复杂话题后，不点任何按钮，项目已存在
2. **找到比管理重要**：10 个项目时，能用搜索 3 秒内找到目标
3. **列表永远清爽**：活跃的项目在上面，不用的自动消失

### 技术验收

4. 自动建项目不打断消息流（fire-and-forget）
5. 重复检测：同一话题不重复建项目（sessionId 幂等）
6. 迁移已有 context/artifacts 到新项目时数据不丢失

## 七、后续展望

完成上述三项后，项目模块的交互模型就彻底从"软件模式"切换到了"人类模式"。下一阶段可考虑：

- **跨项目搜索**：一句话搜所有项目中的内容（"帮我找上次讨论数据库设计的那个项目"）
- **项目摘要**：AI 自动生成项目一句话描述，显示在列表中（替代手动写描述）
- **自然语言切换**："继续上次的记账项目" → 自动切换到对应项目
