## 2. 要因分析

### 2.1 直接根因（主因）：T9' 新增工具 `skills_list` / `skill_view` 未注册到 ToolRegistry

系统有**两条**内置工具注册路径，本次新增的工具只进了其中一条：

| 注册路径 | 入口 | 是否包含 skills_list/skill_view |
|---------|------|:---:|
| 路径 A：ToolManager loaders | `ToolManagerUtils.getBuiltinToolLoaders()` → `ToolManager.registerBuiltinToolsFromLoaders()` → **ToolRegistry** | ❌ 缺失 |
| 路径 B：工具池 | `ToolFactory.getAllBaseTools()` → `getTools()`/`assembleToolPool()` | ✅ 有（L1179-1180） |

**证据链**：
1. `ToolManagerUtils.getBuiltinToolLoaders()`（[ToolManagerUtils.ts](file:///e:/PY/Documents/CODES/PY_APP/app/src/tools/utils/ToolManagerUtils.ts#L68-L256)）只注册了 `createSkillTool`（L83），**没有** SkillListTool/SkillViewTool 的 loader；
2. `ToolFactory` 只有 `createSkillTool()` 工厂方法，**没有** `createSkillListTool()` / `createSkillViewTool()`（[ToolFactory.ts](file:///e:/PY/Documents/CODES/PY_APP/app/src/tools/ToolFactory.ts#L431-L433)）；
3. SkillListTool/SkillViewTool 只在 `getAllBaseTools()`（[ToolFactory.ts](file:///e:/PY/Documents/CODES/PY_APP/app/src/tools/ToolFactory.ts#L1177-L1180)）被 push——但该函数服务于"工具池"路径，**不进入 ToolRegistry**；
4. 模型 tools 参数来自 `registry.getToolSchemas()`（[ChatOrchestrator.ts](file:///e:/PY/Documents/CODES/PY_APP/app/src/chat/orchestrator/ChatOrchestrator.ts#L493-L496)）→ 模型**看不到** skills_list/skill_view；
5. `ToolSearchTool.execute` 用 `getToolRegistry()` + `findToolByName` 查找（[ToolSearchTool.ts](file:///e:/PY/Documents/CODES/PY_APP/app/src/tools/ToolSearchTool/ToolSearchTool.ts#L280-L317)）→ 搜不到 → `matches: []`。

**循环触发闭环**：
```
T9' 渐进式披露注入 <available_skills> 提示
  → 明确引导："用 skills_list 查看全部技能与描述；用 skill_view(name) 加载完整内容"
    （SkillInjectionService.getInjectionPrompt）
  → 模型尝试使用 skills_list / skill_view
  → 但模型 tools 参数（registry.getToolSchemas）不含这两个工具
  → 模型只能通过 tool_search 搜索
  → tool_search 从 ToolRegistry 查找 → 不存在 → matches: []
  → 模型换个关键词/组合再搜 → 仍空 → 死循环
```

### 2.2 放大根因（次因）：循环防护阈值过宽，无"无进展熔断"

即使直接根因存在，模型也不应无限循环。三道防护均未拦截：

| 防护机制 | 阈值/条件 | 为何未拦截 |
|---------|----------|-----------|
| `MAX_TOOL_TURNS`（[ChatManager.ts](file:///e:/PY/Documents/CODES/PY_APP/app/src/chat/ChatManager.ts#L336-L341)） | **默认 300** 轮 | 阈值过宽，循环跑满 249 轮仍未到上限 |
| loopDetector（ReActToolLoop L452-468） | 仅 critical 级"相同工具调用"检测 | 循环是"不同工具组合反复尝试"，非相同调用，不触发 |
| circuitBreaker（ReActLoop.run L206-239） | 连续 3 轮 **all-error** | `config list` 等调用成功，非全错误，不触发 |

> 补充：`sessions status` 反复因"sessionId is required"失败（模型传参错误，L55/L103/L194 等），与 tool_search 空结果叠加，构成典型的"无进展但非全错"循环——恰好绕过全部现有熔断条件。

---

## 3. 影响

- 单次对话工具轮次膨胀至 249 轮，消耗大量 token（模型反复搜索同一批关键词）；
- 长循环期间 provider 流式 TTFB 超时（idleMs 360032），触发多次 `llm_interrupt_retry`；
- `unhandledRejection`（TimeoutError / AbortError）未捕获上报（05:25、05:34）；
- 后台压缩 `[full]` 多次被中止（05:36、05:39）。

---

## 4. 修复建议

### 4.1 主因修复（必须，CS01 归一化）

1. **ToolFactory 增加工厂方法**：`createSkillListTool()` / `createSkillViewTool()`（返回 `new SkillListTool()` / `new SkillViewTool()`）；
2. **ToolManagerUtils.getBuiltinToolLoaders() 增加两个 loader**（对齐 createSkillTool 的注册方式）：
   ```typescript
   createToolLoader(ToolFactory.prototype.createSkillListTool),
   createToolLoader(ToolFactory.prototype.createSkillViewTool),
   ```
3. 注册后验证：`tool_search select:skills_list` 应返回命中，且模型 tools 参数（`registry.getToolSchemas()`）包含 `skills_list`/`skill_view`。

> 根因本质：**同一批工具存在双注册路径且未同步**（ToolManager loaders 与 getAllBaseTools 工具池）。建议后续核查是否还有其他"仅注册到工具池、未注册到 ToolRegistry"的工具（归一化检查 CS01-001）。

### 4.2 放大根因修复（必须，防再犯）

4. **收紧 `MAX_TOOL_TURNS` 默认值**：300 → 建议 20-30（现有长任务可通过 `MAX_TOOL_TURNS` 环境变量按需放宽）；
5. **新增"无进展熔断"**：连续 N 轮（建议 5）工具调用**结果无实质变化**（如 tool_search 连续空结果、同一工具重复失败、token 消耗无下降）时强制终止并提示用户，而非仅依赖 all-error 熔断；
6. **tool_search 空结果提示增强**：`select:<name>` 未命中时，在返回中附带"已注册工具名列表"（或最接近的候选名），帮助模型快速放弃错误目标，避免反复换词搜索。

### 4.3 配套修复（建议）

7. `sessions status` 缺 sessionId 时，错误信息引导模型使用 `sessions list` 获取 id（当前仅报"sessionId is required"）；
8. `unhandledRejection`（TimeoutError/AbortError）应统一走 `handleError` 记录堆栈，避免裸报。

## 5. 验证方式

修复后重启后端（`bun run dev` 自动加载），触发一次技能相关任务（如"查看当前技能列表"）：
- 期望：模型直接调用 `skills_list`（tools 参数可见）→ 无需 tool_search → 1-2 轮内完成；
- 回归：确认 `tool_search select:skills_list` 返回 `matches: ["skills_list"]`；
- 防护验证：故意触发无进展循环，确认在 20-30 轮内被强制终止。
