## 背景与原则

### 为什么需要中文化

1. **身份一致性**：AI 应使用用户母语（中文）思考和工作，语言即身份
2. **消除混淆**：中英混杂的提示词可能导致 AI 在回复语言上摇摆不定
3. **统一体验**：工具提示词已全部为中文，但系统级提示词仍为英文，形成分裂

### 中文化原则

- **正文全中文**：所有提示词指令、描述、说明使用中文
- **保留英文**：以下内容保持英文不变：
  - 代码中保留的英文标识符（如 `<analysis>`、`<summary>` 标签、JSON 字段名）
  - 技术术语（如 `stdout`、`stderr`、`exitCode`、`API`）
  - 特殊标记（`[Previous conversation summarized]` 等）
- **注释保持中文**：代码中的注释使用中文（已有中文的保留，英文的翻译）
- **常量/变量名保持英文**：提示词字符串的变量名（如 `BASH_TOOL_PROMPT`）保持英文不变

### i18n 规划

1. **当前阶段**：全中文提示词（不引入 i18n 框架）
2. **第二阶段**：用简单 i18n 机制（如 key-value JSON 文件）统一管理提示词
3. **第三阶段**：多语言支持（中/英/日等），通过用户配置选择语言

> 当前仅执行第一阶段，直接替换提示词正文为中文字符串。后续阶段时机成熟时另行规划。

## 中文化实施计划

### 总体方案

```
1. 先做 D 类（杂项，风险最低）→ 熟悉流程
2. 再做 A 类（身份与行为提示词，影响面广但量少）
3. 再做 C 类（记忆提取，中等复杂度）
4. 最后做 B 类（对话压缩，最复杂）
```

### 执行顺序

| 优先级 | 文件 | 预估工作量 | 说明 |
|-------|------|----------|------|
| 🥇 1 | `buddy/prompt.ts` | 1 处，~10 行 | 低风险，可快速完成 |
| 🥇 2 | `constants/prompts.ts` | ~18 处语句 | 低风险，纯字符串替换 |
| 🥇 3 | `context/PromptTemplates.ts` | ~8 条语句 | 影响系统身份，但修改简单 |
| 🥇 4 | `constants/systemPromptSections.ts` | ~1 段落 | 同上 |
| 🥇 5 | `services/SessionMemory/prompts.ts` | ~1 模板 | 简单模板翻译 |
| 🥈 6 | `services/extractMemories/prompts.ts` | ~50 行 | 中等复杂度，需保留输出协议 |
| 🥉 7 | `services/compact/prompt.ts` | ~280 行 | 最复杂，需仔细处理输出格式协议 |

### 注意事项

1. **保留协议标记**：`TYPE:` / `TITLE:` / `CONTENT:` / `CONFIDENCE:`、`<analysis>` / `<summary>`、`\`\`\`` 等格式标记保持英文
2. **保留技术术语**：`stdout`、`stderr`、`exitCode`、`API`、`JSON`、`Git`、`PID` 等保持英文
3. **保留代码标识符**：`task_id`、`file_path`、`operation` 等 JSON 字段名保持英文
4. **不修改变量名**：提示词字符串的导出变量名（如 `BASH_TOOL_PROMPT`）保持英文不变
5. **保持换行和缩进**：中文化后保持原有换行和缩进格式
6. **注释使用中文**：已有注释（如 `基于CC源码`）保持中文
